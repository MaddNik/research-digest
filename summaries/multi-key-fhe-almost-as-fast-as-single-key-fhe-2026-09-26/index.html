Multi-Key FHE Almost as Fast as Single-Key FHE

IACR ePrint Archive, Paper 2026/2195 · full view ↗

Overview and Problem Statement

This paper, by Abtin Afshar and Rishab Goyal (University of Wisconsin-Madison), addresses a long-standing open question in multi-key fully homomorphic encryption (MKFHE). MKFHE extends ordinary FHE by letting users generate keys and encrypt independently; an evaluator can later pick a set of $N$ users, compute jointly on their ciphertexts, and produce an output that those users can jointly decrypt. Applications include round-optimal multiparty computation, multi-key homomorphic secret sharing, communication-preserving MPC compilers, threshold cryptography, and privacy-preserving distributed machine learning.

The concatenation barrier. Every prior MKFHE scheme accommodates independently generated keys by expanding each ciphertext under the concatenation $\hat{t} = (t_1,\ldots,t_N)$ of the participating users' secret keys, and then evaluating circuits in this $N$-times-larger dimension. Because the key grows linearly with $N$, so does ciphertext size and per-gate cost: GSW-based schemes (Clear-McGoldrick, Mukherjee-Wichs) use $nN \times mN$ matrices with $O(nm^2N^3)$ field operations per multiplication; BFV-based schemes (CDKS) use $N+1$ ring elements with $O(N^2)$ work per multiplication. Lopez-Alt, Tromer and Vaikuntanathan, who introduced MKFHE, explicitly asked for a scheme where all algorithms are independent of $N$. More than a decade later, no MKFHE scheme had achieved even a sub-linear dependence on $N$ for homomorphic evaluation.

A recent related work by the same authors, Afshar-Goyal (CRYPTO 2026, ePrint 2026/1683), designed an MKFHE scheme with evaluated ciphertexts of size $\ell + \mathrm{poly}(\lambda, d, \log N)$ for an $\ell$-bit output, using succinct oblivious tensor evaluation. However, that scheme is a compression wrapper applied only after evaluation finishes: the evaluator's working dimension, running time, and working space during evaluation still scale polynomially with $N$ for every gate.

This paper asks: can multi-key homomorphic evaluation have the same per-gate cost as single-key evaluation, with every evaluated ciphertext, every gate, and the decryptable output independent of $N$, while users still generate keys and encrypt independently and the participating set is chosen only after encryption? The paper answers this affirmatively.

Main Idea: Sum Instead of Concatenation

The key structural change is to replace the concatenated key $\hat{t}=(t_1,\ldots,t_N)$ with a virtual key that is the sum of the participating users' secrets, $\tilde{s} = \sum_{i=1}^N s_i$, $\tilde{t} = (-\tilde{s}^\top, 1)^\top$. The construction inserts a public, deterministic, non-interactive preprocessing phase between encryption and evaluation, consisting of two new algorithms:

  • Key aggregation (KeyAgg): combines the selected users' public keys into a preparation key $\mathsf{PrepKey}$ and an evaluation key $\mathsf{EvalKey}$. This is a one-time cost per participating set, reused across all inputs and circuits for that set.
  • Ciphertext preparation (CTPrep): uses $\mathsf{PrepKey}$ to convert one independently-generated fresh ciphertext (encrypted before the participating set was even chosen) into a short single-key ciphertext under the virtual key $\tilde t$ (or $\tilde\sigma$ in the ring case).

After preparation, every wire ciphertext is an ordinary single-key ciphertext under the common virtual key, so evaluation runs with completely ordinary single-key homomorphic gate operations, independent of $N$. The only place where cost scales with $N$ is the public preprocessing phase (key aggregation and ciphertext preparation), which happens once per user set and is never repeated during circuit evaluation. Both KeyAgg and CTPrep are deterministic, require no secret keys, and can be run by an untrusted evaluator using only published material.

Two concrete instantiations are given:

  • GSW-based, over $\mathbb{Z}_q$, from standard LWE (Section 4): converts expanded Mukherjee-Wichs (MW) ciphertexts into ordinary $n\times m$ GSW matrices. GSW multiplication needs no evaluation key, so the challenge is purely in ciphertext preparation.
  • BFV-based, over cyclotomic rings, from circular Ring-LWE (Section 5): converts each input into an ordinary two-ring-element BFV ciphertext. Here BFV multiplication requires relinearization under the virtual secret, which is the harder technical problem since the square of a sum of secrets contains cross terms that no single user can compute from its own secret alone.

Both constructions retain single-round distributed decryption with statistically simulatable partial decryptions (the standard smudging technique), at the cost of published key material that still grows with $N$. As a proof of concept, the ring-based construction is implemented in Go; for 32 users its multiplication is $275.13\times$ faster than CDKS and $45.50\times$ faster than KKLSS, with ciphertexts $16.5\times$ smaller than both.

Formal Efficiency Notions: Full Succinctness and Optimal Evaluation

The paper formalizes the syntax of an MKFHE scheme with the standard algorithms $\mathsf{Setup}, \mathsf{KeyGen}, \mathsf{Enc}, \mathsf{Dec}$, plus the two new public algorithms $\mathsf{KeyAgg}$ and $\mathsf{CTPrep}$ inserted between encryption and evaluation:

  • $\mathsf{Setup}(1^\lambda, 1^d, 1^N) \to \mathsf{PP}$: security parameter, circuit-depth bound, and number of users.
  • $\mathsf{KeyGen}(\mathsf{PP}, i) \to (\mathsf{PK}_i, \mathsf{SK}_i)$.
  • $\mathsf{Enc}(\mathsf{PP}, \mathsf{PK}_i, \mu) \to \mathsf{CT}$.
  • $\mathsf{KeyAgg}(\mathsf{PP}, (\mathsf{PK}_i)_{i\in[N]}) \to (\mathsf{PrepKey}, \mathsf{EvalKey})$: public, deterministic.
  • $\mathsf{CTPrep}(\mathsf{PP}, \mathsf{PrepKey}, \mathsf{CT}) \to \mathsf{CT}^{\mathrm{prep}}$: public, deterministic.
  • $\mathsf{Eval}(\mathsf{PP}, \mathsf{EvalKey}, C, (\mathsf{CT}^{\mathrm{prep}}_i)_{i\in[N]}) \to \mathsf{CT}_C$.
  • $\mathsf{Dec}(\mathsf{PP}, (\mathsf{SK}_i)_{i\in[N]}, \mathsf{CT}_C) \to \mu$.

The usual requirements of correctness, semantic security, and compactness ($|\mathsf{CT}_C| \le \mathrm{poly}(\lambda, d, N, |C(\cdot)|)$) are imposed, plus two sharper efficiency definitions:

Definition (Full Succinctness). The evaluated ciphertext size satisfies $|\mathsf{CT}_C| \le \mathrm{poly}(\lambda, d, \log N, |C((\mu_i)_{i\in[N]})|)$, i.e. only logarithmic, not polynomial, dependence on $N$.

Definition (Optimal Evaluation). There is a fixed polynomial such that $|\mathsf{EvalKey}|$ and the running time of each gate are bounded by $\mathrm{poly}(\lambda, d, \log N)$, and total evaluation time is bounded by $|C| \cdot \mathrm{poly}(\lambda, d, \log N)$. Crucially, the time spent on key aggregation and ciphertext preparation may still grow polynomially in $N$, only per-gate evaluation cost must be essentially independent of $N$.

The paper's main theorems show that both the GSW-based and BFV-based constructions achieve full succinctness and optimal evaluation. The paper also formalizes a dynamic choice of users remark: setup fixes only a maximum $N_{\max}$; users generate keys and encrypt before any participating set $S\subseteq [N_{\max}]$ or circuit is chosen, and aggregation/preparation are later restricted to $S$ with its members relabeled.

Single-round distributed decryption is captured by two further algorithms, $\mathsf{PartDec}$ and $\mathsf{FinDec}$, satisfying correctness of partial decryption and a simulatability property: each party's partial decryption share is statistically close to a value produced by a simulator that does not use that party's secret key, given the final output. This is achieved via the standard smudging technique (adding large uniform noise that statistically drowns the small decryption error).

Technical Overview: From GSW to the Virtual Key

The GSW relation. A single-key GSW ciphertext of a bit $\mu$ is a matrix $C \in \mathbb{Z}_q^{n\times m}$ satisfying, for the augmented secret key $t=(-s^\top,1)^\top$ and public gadget matrix $G=[I_n\otimes g^\top \mid 0]$ built from $g=(1,2,\ldots,2^{\log q -1})^\top$:

$$t^\top C = \mu\, t^\top G + e^\top$$

where $e$ is a short error vector. Because $G$ admits a public bounded decomposition $G^{-1}$ with $GG^{-1}(x)=x$, the bit encoded in $C$ behaves like an approximate eigenvalue under eigenvector $t$, and $C_1+C_2$ and $C_1 G^{-1}(C_2)$ homomorphically add and multiply, with no evaluation key at all.

Reading the relation column by column: for the column aligned with $2^\alpha e_k$ in $G$, its phase is $t^\top c_{k,\alpha} \approx \mu 2^\alpha t_k$, which equals $-\mu 2^\alpha s_k$ for $k

The Mukherjee-Wichs (MW) expansion. In the multi-key setting, each user $i$ independently encrypts with its own secret $s_i$. A fresh ciphertext contains a GSW matrix $C$ plus auxiliary encryptions $U$ of its own randomness, which support public expansion to a matrix $\hat C \in \mathbb{Z}_q^{nN\times mN}$ satisfying

$$\hat t^\top \hat C \approx \mu\, \hat t^\top \hat G_N, \qquad \hat t = (t_1^\top,\ldots,t_N^\top)^\top, \qquad \hat G_N = I_N \otimes G.$$

$\hat C$ has $N$ block rows (one per user's key) and $N$ column groups (one per user who encrypted), so its size grows as $N^2$ and multiplication grows as $N^3$. This concatenation is identified as the structural root cause of every cost that scales with $N$ in prior MKFHE.

Replacing concatenation with a sum. The paper's target relation is, for the virtual key $\tilde t = (-\tilde s^\top, 1)^\top$ with $\tilde s = \sum_{i=1}^N s_i$:

$$\tilde t^\top \mathsf{CT} \approx \mu\, \tilde t^\top G.$$

Since this is exactly the single-key GSW relation with $t$ replaced by $\tilde t$, any ciphertext satisfying it is an ordinary GSW ciphertext and evaluates at single-key dimension with no evaluation key. The virtual key $\tilde t$ is never reconstructed by any algorithm and is not known to any single user; it exists only implicitly as the sum of the chosen users' secrets.

Preparation (CTPrep) composes three public operations on one fresh input $(U, C)$:

  1. Expand: ordinary MW expansion, $(U,C) \to \hat C \in \mathbb{Z}_q^{nN \times mN}$, under the concatenated key $\hat t$. No gate is ever applied to $\hat C$; it is only a stepping stone.
  2. Compress rows: shorten every column of $\hat C$ from $nN$ to $n$ coordinates while preserving its phase, changing the key on the left from $\hat t$ to $\tilde t$, yielding $Z \in \mathbb{Z}_q^{n\times mN}$.
  3. Reduce columns: fold the $N$ user-indexed column groups into the single group that $G$ prescribes, changing the encoded values on the right, yielding $\mathsf{CT} \in \mathbb{Z}_q^{n\times m}$.

In the actual Section 4 construction these last two steps are applied in reverse order (select/sum columns first, then compress) to reduce both work and accumulated error, since only $m$ compressions are then needed instead of $mN$.

Vector Compression: the Core Cryptographic Gadget

The crux of the construction is a way to shrink an $nN$-coordinate column (phased under the concatenated key $\hat t$) down to an $n$-coordinate column phased (approximately) under the virtual key $\tilde t$, using only public material.

Naive masking and its cancellation. For an expanded column $c\in\mathbb{Z}_q^{nN}$ with user blocks $c_j\in\mathbb{Z}_q^n$, its phase is

$$\hat t^\top c = \sum_j c_{j,n} - \sum_{j,k

The first sum is public; the second involves every user's secret coordinates, none of which the evaluator knows. Fix a common public mask $a_{j,k} \in \mathbb{Z}_q^{n-1}$. Each user $i$ publishes

$$w_{i,j,k} = \langle s_i, a_{j,k}\rangle + \delta_{i,j} s_{i,k} + \varepsilon_{i,j,k},$$

where $\delta_{i,j}$ is the Kronecker delta and $\varepsilon_{i,j,k}$ is a small error. Summing over all $i$:

$$W_{j,k} = \sum_i w_{i,j,k} = \langle \tilde s, a_{j,k}\rangle + s_{j,k} + \varepsilon_{j,k}, \qquad \tilde t^\top \begin{pmatrix}a_{j,k}\\ W_{j,k}\end{pmatrix} = s_{j,k} + \varepsilon_{j,k}.$$

Each user contributes its share of the mask, while only user $j$ inserts the secret coordinate being encoded; summing cancels the mask under the virtual key, even though no user knew the virtual secret when publishing its contribution. A naive version of this (without digit decomposition) fails: ciphertext coefficients $c_{j,k}$ can be as large as $q$, so multiplying by them can amplify even a tiny encoding error $\varepsilon_{j,k}$ past the decryption margin.

Controlling error via gadget decomposition. The fix publishes encodings of $2^\alpha s_{j,k}$ for each power of two $\alpha$ separately, using an independent mask per power: $K_{j,k,\alpha}$ with phase $\tilde t^\top K_{j,k,\alpha} = 2^\alpha s_{j,k} + \varepsilon_{j,k,\alpha}$. Writing $c_{j,k} = \sum_\alpha 2^\alpha \beta_{j,k,\alpha} \pmod q$ in binary digits $\beta_{j,k,\alpha}$,

$$\mathrm{Compress}(c) = \begin{pmatrix}0_{n-1}\\ \sum_j c_{j,n}\end{pmatrix} - \sum_{j,k

Now each aggregated error term $\varepsilon_{j,k,\alpha}$ is multiplied by only $0$ or $1$ (the digit $\beta_{j,k,\alpha}$), controlling error growth to a sum of at most $N(n-1)\log q$ bounded terms rather than a sum weighted by arbitrary ring elements up to $q$. This compression is independent of the plaintext: it applies equally to an expanded column, a sum of such columns, or a decryption vector.

Lemma (Ciphertext compression, formalized in Section 4.1). For every $c \in \mathbb{Z}_q^{nN}$,

$$\tilde t^\top \mathrm{Compress}(c) = \hat t^\top c - \sum_{j,k,\alpha} \beta_{j,k,\alpha}\varepsilon_{j,k,\alpha},$$

with the added compression error bounded by $N^2(n-1)\log q\, B_{\mathrm{cmp}}$, and running time (after preprocessing) $O(Nn^2\log q)$.

Column reduction. After compression, the matrix still has $N$ column groups, one per user, each still phased by that user's individual secret coordinate $s_{j,k}$ rather than the summed $\tilde s_k$. Adding columns at the same $(k,\alpha)$ position across all $N$ users adds their phases: $\tilde t^\top(z_{1,k,\alpha}+\cdots+z_{N,k,\alpha}) \approx -\mu 2^\alpha(s_{1,k}+\cdots+s_{N,k}) = -\mu 2^\alpha \tilde s_k$, exactly the needed value. For the constant coordinate $k=n$ (where every group already carries phase $\mu 2^\alpha$, since every augmented key ends in $1$), only one group's column is kept and the rest are discarded (summing all $N$ would overshoot to $N\mu 2^\alpha$). This gives the prepared ciphertext $\mathsf{CT}=Y$ satisfying the target GSW relation under $\tilde t$.

Section 4: Fast GSW-Based MKFHE from Plain LWE

Construction 4.2 formalizes the full scheme over $\mathbb{Z}_q$ for an odd prime $q$, $\Delta=(q-1)/2$, gadget $G=G_{n,m}$, secrets $s_i \in \mathbb{Z}_q^{n-1}$.

Setup: samples the common MW matrix $B \leftarrow \mathbb{Z}_q^{(n-1)\times m}$ and, for every $j\in[N]$, $k\in[n-1]$, $\alpha\in\{0,\ldots,\log q -1\}$, independent uniform masks $a_{j,k,\alpha} \in \mathbb{Z}_q^{n-1}$.

KeyGen($i$): samples $s_i \leftarrow \mathbb{Z}_q^{n-1}$, error $e_i\leftarrow\chi^m$, and compression errors $\varepsilon_{i,j,k,\alpha}\leftarrow\chi_{\mathrm{cmp}}$; forms the MW key pair $\mathrm{pk}_i = A_i=[B; b_i^\top]$ with $b_i=B^\top s_i + e_i$, $\mathrm{sk}_i = t_i=(-s_i^\top,1)^\top$; and publishes the compression entries $w_{i,j,k,\alpha} = \langle s_i, a_{j,k,\alpha}\rangle + \delta_{i,j}2^\alpha s_{i,k} + \varepsilon_{i,j,k,\alpha}$.

Enc: ordinary MW encryption producing $(U,C)$.

KeyAgg: sums $W_{j,k,\alpha} = \sum_i w_{i,j,k,\alpha}$ to form compression key $CK$; outputs $\mathsf{PrepKey}=((\mathrm{pk}_j)_j, CK)$ and empty $\mathsf{EvalKey}=\bot$ (GSW needs no evaluation key).

CTPrep: runs MW public expansion using $U$ and the public keys to get $\hat C$, applies the public column-selection matrix $H$ to get $Y=\hat C H \in \mathbb{Z}_q^{nN\times m}$, then column-wise compresses: $\mathsf{CT}^{\mathrm{prep}} = \mathrm{Compress}^{\mathrm{col}}(Y) \in \mathbb{Z}_q^{n\times m}$.

Eval: ordinary GSW evaluation of circuit $C$ on prepared ciphertexts.

Dec: each party reconstructs $\tilde s=\sum_i s_i$, $\tilde t = (-\tilde s^\top,1)^\top$, computes $c_{\mathrm{out}} = \mathsf{CT}_C G^{-1}(\Delta e_n)$, $z=\tilde t^\top c_{\mathrm{out}}$, and outputs $\mu = \lceil z\rfloor_2$ (rounding to nearest multiple of $\Delta$).

Computing without materializing the full expansion. A crucial efficiency point: a fresh MW expansion consists of $N$ diagonal copies of the same $n\times m$ matrix $C$ and only $N-1$ correction blocks $X_j$ in the owner's block row (all other blocks are zero). The construction computes these $O(N)$ nonzero blocks one at a time, accumulates only the columns selected by $H$, and compresses them, without ever materializing the full $nN\times mN$ matrix $\hat C$. This makes preparation linear rather than quadratic in $N$ for the indexed variant.

Theorem 1.1 (informal). Assuming LWE, there is a leveled MKFHE where every prepared or evaluated ciphertext is an $n\times m$ matrix over $\mathbb{Z}_q$. Homomorphic addition costs $O(nm)$ field operations, homomorphic multiplication costs $O(nm^2)$ field operations, and no evaluation key is required. In the indexed variant, key aggregation costs $O(N^2 n)$ and ciphertext preparation costs $O(Nnm^2)$ field operations. In the unindexed variant (Appendix C transformation), these costs become $O(N^2n^2m^2)$ and $O(n^2m^2)$ respectively. Here $n-1$ is the LWE dimension and $m = n\lceil \log_2 q\rceil + 2\lambda$.

Parameter settings. Take $n = \lceil(\lambda+d+\log(N+1))^2\rceil$, $\chi$ the truncated discrete Gaussian with bound $B_\chi = n\sqrt\lambda$, $\chi_{\mathrm{cmp}}=\chi$, $m=n\log q + 2\lambda$. MW's fresh expansion has error at most $B_{\mathrm{MW}}=(m^4+m)B_\chi$; the preparation error is bounded by $B_{\mathrm{in}}(N) = NB_{\mathrm{MW}} + N^2(n-1)\log q\, B_\chi$; ordinary GSW evaluation increases this by a factor of at most $m+1$ per level, so $q$ must satisfy $(\log q)(m+1)^d B_{\mathrm{in}}(N) < q/4 - 1/2$, achievable with $\log q = O((d+1)\log(\lambda+d+\log(N+1)) + \log(N+1))$. Security assumes $\mathrm{LWE}_{n-1,q,\chi}$ with $m+N(n-1)\log q$ samples per secret.

Security. The public keys now also contain the compression entries $w_{i,j,k,\alpha}$, which are linear key-dependent messages (KDM) of the secret $s_i$. The paper proves security of this linear-KDM structure directly from ordinary LWE via a public-mask translation in the style of affine-KDM security (Applebaum-Cash-Peikert-Sahai), without any extra circular-security assumption: given LWE challenge samples under the challenge user's secret, the reduction can publicly shift the masks so that the challenge samples exactly realize the compression entries. Together with the leftover hash lemma (used, as in MW, on the GSW encryptions of randomness and on the message-bearing matrix), this establishes full semantic security, which is preserved after public preparation and evaluation since those are public computations.

Distributed decryption (Section 4.5). Using a larger modulus $q$ with error bound $B_{\mathrm{dec}} = (\log q)(m+1)^d B_{\mathrm{in}}(N)$ and smudging bound $B_{\mathrm{sm}}$ chosen so that $B_{\mathrm{dec}}/B_{\mathrm{sm}} = \mathrm{negl}(\lambda)$ and $B_{\mathrm{dec}} + NB_{\mathrm{sm}} < q/4-1/2$: each party computes $c_{\mathrm{out}}=\mathsf{CT}_C G^{-1}(\Delta e_n) = (u^\top,v)^\top$, sets $\gamma_i = \delta_{i,1}v - \langle s_i,u\rangle$, samples smudging noise $e^{\mathrm{sm}}_i$ uniformly in $[-B_{\mathrm{sm}},B_{\mathrm{sm}}]$, and outputs $p_i = \gamma_i + e_i^{\mathrm{sm}} \pmod q$. Final decryption rounds $\sum_i p_i$. Simulatability follows because the real share differs from a simulated one only by the small decoding error $\varepsilon$, which is statistically drowned by the smudging noise (distance $B_{\mathrm{dec}}/(2B_{\mathrm{sm}}+1) = \mathrm{negl}(\lambda)$).

Section 5: Fast BFV-Based MKFHE from Ring-LWE

Over rings $R_q = \mathbb{Z}_q[X]/(X^n+1)$ with $n$ a power of two, messages in $R_t$, $\Delta=(q-1)/t$, a BFV ciphertext is a pair $(c_0,c_1)$ with phase $c_0+c_1 s \approx \Delta\mu$. CDKS expands this to a vector $(c_0,\ldots,c_N)$ under the concatenated key $(1,s_1,\ldots,s_N)$. Because a BFV ciphertext already represents the message through a single phase (not a matrix of phases as in GSW), expansion simply inserts zeros at the non-owner positions; there is no analogue of GSW's column-reduction step, so preparation over rings is actually simpler than over fields.

Compression over the ring. Each user independently samples a compression secret $\sigma_i$ (distinct from its BFV secret $s_i$); the virtual secret is $\tilde\sigma = \sum_i \sigma_i$. With a gadget $(h,g)$ of length $k$ and uniform masks $a_j \in R_q^k$, users publish $w_{i,j} = \sigma_i a_j + \delta_{i,j} s_i g + e_{i,j}$; aggregation gives $W_j = \sum_i w_{i,j} = \tilde\sigma a_j + s_j g + E_j$. For a source column $c=(c_0,\ldots,c_N)$, compression computes $u = \sum_j \langle h(c_j), a_j\rangle$, $v = c_0 + \sum_j \langle h(c_j), W_j\rangle$, yielding a pair $(v,-u)$ with phase $v - u\tilde\sigma \approx c_0 + \sum_j c_j s_j$: an ordinary two-element BFV pair under the virtual secret $\tilde\sigma$.

The new obstacle: relinearization. Addition of prepared pairs is trivially componentwise. Multiplication is not free in BFV (unlike GSW) because it needs secret-dependent public material (a relinearization key). Scaling and rounding the product of two phases under $\tilde\sigma$ leaves

$$(c_0+c_1\tilde\sigma)(c_0'+c_1'\tilde\sigma) \rightsquigarrow T_0 + T_1\tilde\sigma + T_2\tilde\sigma^2,$$

and relinearization must replace $T_2\tilde\sigma^2$ with a term linear in $\tilde\sigma$. The square $\tilde\sigma^2 = \left(\sum_i\sigma_i\right)^2$ contains cross terms, e.g. for two users $(\sigma_1+\sigma_2)^2 = \sigma_1^2 + 2\sigma_1\sigma_2 + \sigma_2^2$. No single user can compute the cross term $\sigma_1\sigma_2$ from its own secret, so simply summing ordinary per-user relinearization keys is not merely lossy, it is wrong.

Aggregating masked relinearization keys. The fix reuses the masked representation from CDKS, specialized to a single secret $\sigma$ with an auxiliary secret $r$ and common public masks $a,u\in R_q^k$:

$$B \approx -\sigma a, \qquad D \approx -ra + \sigma g, \qquad V \approx -\sigma u - rg.$$

Each secret appears only to degree one, multiplied by public coefficients, so these equations are (a) satisfiable by each user from its own secret alone, (b) linear in that secret, so summing per-user contributions yields the same equations for the summed secrets, and (c) sufficient at gate time to manufacture the needed quadratic term. User $i$ publishes $b_i=-\sigma_i a + e_{B,i}$, $d_i=-r_i a + \sigma_i g + e_{D,i}$, $v_i = -\sigma_i u - r_i g + e_{V,i}$ using a freshly sampled $r_i$; summing gives $(B,D,V)$ satisfying the above for $(\sigma,r)=(\tilde\sigma,\tilde r)$, $\tilde r=\sum_i r_i$. Crucially, the mask $u$ is common across users (unlike plain CDKS, which samples $u$ per user), which is exactly what makes the per-user contributions $\sigma_i u$ add up to $\tilde\sigma u$.

Compact multiplication (FastMult). Given $(B,D,V)$ and two prepared ciphertexts, compute the tensor $(T_0,T_1,T_2)$ by scaling and rounding (as in ordinary BFV), decompose $z=h(T_2)$, compute $x=\langle z,B\rangle \approx -\sigma\langle z,a\rangle$, and output the pair

$$\big(\langle h(x), V\rangle,\ \langle z, D\rangle + \langle h(x), u\rangle\big),$$

which has phase $\approx \sigma^2 T_2$ (the $D$ term supplies $\sigma^2 T_2$ together with a mask in $r$; the $V$/$u$ term supplies the opposite mask, canceling it). Adding $T_0$ and $T_1$ to the two components yields a new ordinary BFV pair encrypting the product, ready for the next gate.

Theorem 1.2 (informal). Assuming circular Ring-LWE, there is a leveled MKFHE where every prepared or evaluated ciphertext consists of two elements of $R_q$. Homomorphic addition and multiplication both cost $O(1)$ ring operations (more precisely $O(k)=O(\log q)$ with binary gadgets). In both indexed and unindexed variants, key aggregation costs $O(N^2)$ and ciphertext preparation costs $O(1)$ ring operations.

Construction 5.1 (summary of algorithms). Setup fixes gadgets $(h_c,g_c)$ and $(h,g)$ and uniform masks $a_j$ (for compression) and $a,u$ (for relinearization). KeyGen samples $s_i,\sigma_i,r_i\leftarrow\chi$, forms the ordinary BFV public key $(b_i,a_i)$ with $b_i=-a_i s_i + e_{\mathrm{pk},i}$, the compression entries $w_{i,j}$, and the masked relinearization vectors. Enc is ordinary BFV encryption. KeyAgg sums the $w_{i,j}$ into $CK=\mathsf{PrepKey}$ and the masked vectors into $(B,D,V)=\mathsf{EvalKey}$. CTPrep applies Compress to the owner's zero-padded column, computing only the owner's terms. Eval runs FastMult at multiplication gates and componentwise addition at addition gates. Dec sums the $\sigma_i$ to get $\tilde\sigma$ and rounds $\frac{t}{q}[c_0+c_1\tilde\sigma]_q$.

Error analysis. With $\delta_R=n$ (the ring expansion factor), $B_s=NB_\chi$, $B_{ek}=NB_e$, preparation/relinearization error bounds are $B_{\mathrm{in}}(N)=2\delta_R B_\chi B_e + B_e + Nk_c\delta_R B_c B_e$ and $B_{\mathrm{rlin}}(N) = 2k\delta_R^2 B_h B_s B_{ek} + k\delta_R B_h B_{ek}$. For a depth bound $d$, setting $\alpha=\delta_R t(2H+4)$, $\beta = H^2+\delta_R t(H+2)+B_{\mathrm{rlin}}(N)$ with $H=\delta_R(1+B_s)$, the noise recurrence $E_{h+1} = \max\{2E_h+1, \alpha E_h+\beta\}$ must stay below $q/(2t)-1/2$ at depth $d$, giving a closed form $E_d = \alpha^d E_0 + \beta(\alpha^d-1)/(\alpha-1)$ and a modulus choice $\log q = O((d+1)\log(2+n+t+N+B_\chi+B_e+d))$.

Security. As in CDKS, the construction assumes circular security of Ring-LWE: the challenge user's compression entries and masked relinearization vectors are jointly indistinguishable from uniform given the public masks and other honestly generated keys. After this replacement, ordinary BFV semantic security under Ring-LWE hides the message, and this is preserved through public KeyAgg, CTPrep, Eval.

Distributed decryption (Section 5.5). Analogous to the field case: $\mathrm{PartDec}$ computes $\gamma_i = \delta_{i,1}c_0 + c_1\sigma_i$ plus uniform smudging noise with coefficients in $[-B_{\mathrm{sm}},B_{\mathrm{sm}}]$, chosen so $nE_d/B_{\mathrm{sm}} = \mathrm{negl}(\lambda)$ and $E_d + NB_{\mathrm{sm}} < q/(2t)-1/2$; $\mathrm{FinDec}$ rounds $\sum_i p_i$. This uses one ring element per user per output polynomial.

The clear pattern: per-gate running time, wire ciphertext size, and decryptable payload all become independent of $N$ (constants $nm$, $nm^2$ over fields; $O(1)$ over rings), matching single-key costs. The price is paid entirely in the preprocessing phase (key aggregation, preparation key, and per-user public key), which remain polynomial (often quadratic) in $N$, though this work can be reused across all circuits and inputs for a fixed user set.

These improvements build on a chain of prior optimizations the paper surveys: over fields, Brakerski-Perlman reduces wire ciphertexts from $N^2nm$ to $Nn$ and fresh ciphertexts from $nm^3$ to $n$; Afshar-Goyal (the companion CRYPTO 2026 paper) reduces payload size from $Nn$ to $n$; over rings, KKLSS and a follow-up (Zhou-Huang-Wang) reduce multiplication from $N^2$ to $N$, and a no-CRS construction removes setup material. This paper is the first to make the per-gate cost itself independent of $N$ rather than merely reducing specific components.

Removing User Indices (Appendix C)

The main constructions assign each user a fixed index at key generation, which the standard MKFHE notion does not require. Appendix C gives a generic transformation (Construction C.1) from an indexed to an unindexed MKFHE scheme, at the cost of larger keys and fresh ciphertexts:

  • Each user samples $N$ independent secrets $s_i^{(1)},\ldots,s_i^{(N)}$ (one per candidate rank position) and publishes the corresponding public keys and compression entries for every candidate position $\ell$.
  • Fresh encryption encrypts the same message under all $N$ candidate keys.
  • Once a participating set is chosen, members are ranked (e.g. lexicographically), and each user's key material/ciphertext for its assigned rank is used; the virtual key is the sum of the selected secrets.

This increases fresh ciphertext size and per-user published material by a factor of $N$, while leaving prepared ciphertexts, gate costs, and decryption unchanged. A refinement using key switching (via a generic PKE scheme whose decryption circuit is evaluated homomorphically) makes encryption produce a single small fresh ciphertext again, at the cost of larger keys, and moves the heavy work from ciphertext preparation into key aggregation (which can be amortized across inputs for a fixed user set).

Theorem C.2 / Corollary C.3. Assuming an indexed leveled MKFHE with full succinctness and optimal evaluation (and, for Corollary C.3, assuming LWE or circular Ring-LWE for the two concrete constructions), the unindexed transformation preserves full succinctness and optimal evaluation.

The transformation works in three conceptual steps for each input ciphertext $\mathsf{ct}^*_i$ encrypted under a generic PKE's public key $\mathrm{pk}^*$: (1) at key generation, the source secret $s_i^*$ is itself encrypted under every candidate indexed key, producing bundles $\mathrm{bk}_i^{(\ell)}$; (2) key aggregation prepares the bundle for the canonically assigned position $i$, obtaining $\widehat{\mathrm{bk}}_i$ under the aggregate (virtual) key; (3) ciphertext preparation homomorphically evaluates the PKE decryption circuit $D_{\mathsf{ct}^*_i}$ on $\widehat{\mathrm{bk}}_i$, which both decrypts $\mathsf{ct}^*_i$ and lands the result directly in the aggregate evaluation domain, requiring no further preparation step.

Over fields, this increases each user's public key from $O(Nn+m)$ to $O(N^2n + Nn^2m^3)$, key aggregation from $O(N^2n)$ to $O(N^2n^2m^2)$, and the preparation key from $O(Nm)$ to $O(Nn^2m)$, while fresh ciphertext size falls from $O(nm^3)$ to $O(n)$ and per-input preparation (now evaluating source decryption) changes from $O(Nnm^2)$ to $O(n^2m^2)$. Over rings, if a compatible source PKE exists with $O(1)$-size keys/ciphertexts and $O(1)$-round decryption circuits (not instantiated in the paper), only the public-key entry changes, from $O(N)$ to $O(N^2)$. A further optimization expands a single PRG seed into all $N$ indexed KeyGen random tapes, so a user's secret key collapses to just that seed.

Related Work and Open Problems

Lineage. MKFHE began with Lopez-Alt, Tromer, Vaikuntanathan's NTRU-based construction for an a-priori bounded number of keys, followed by LWE-based schemes with quadratic expanded ciphertexts (Clear-McGoldrick; Mukherjee-Wichs). Subsequent work achieved multi-hop evaluation without bootstrapping (Peikert-Shiehian), linear ciphertext length via branching programs (Brakerski-Perlman), and batched multi-hop evaluation over rings (Chen-Zhang-Wang). CDKS and KKLSS gave practical ring-based evaluation. Other lines studied distributed setup (Brakerski-Halevi-Polychroniadou), plain-model constructions (Ananth-Jain-Jin-Malavolta; a no-CRS construction cited as MPS26), and circuit privacy against maliciously generated keys (Chongchitmate-Ostrovsky). DHRW's additive-function-sharing spooky encryption produces individually-keyed ciphertexts whose plaintexts sum to a function output, a related but distinct primitive.

Closest prior work: Afshar-Goyal (AG26). Obtains evaluated ciphertexts of size $\ell + \mathrm{poly}(\lambda)$ under plain LWE by compressing the decryption information of an already-expanded ciphertext, using succinct oblivious tensor evaluation (Abram-Malavolta-Roy, STOC 2025). That compressed object supports plaintext recovery but does not itself satisfy the GSW relation or the BFV relation, and evaluation still runs in the expanded $N$-dependent dimension; only the final output is compressed. The present work instead preserves the GSW/BFV relations throughout and evaluates at single-key dimension from the start, at the price of $O(N)$ compression entries published per user. AG26's route is specific to plain LWE (no known ring analogue of succinct oblivious tensor evaluation), whereas the present work covers both fields and rings.

Summed keys elsewhere. Summed secret keys already appear in threshold/multiparty HE when the party set is fixed before encryption (e.g. Asharov-Jain-Lopez-Alt-Tromer-Vaikuntanathan-Wichs; Boneh et al.; Mouchet et al.; Kim-Lee-Seo-Wang). Multi-key TFHE reduces per-gate cost from quadratic to quasi-linear in $N$ (Chen-Chillotti-Song; Kwak-Min-Seo; Akin-Klemsa-Onen; recent follow-ups). In particular, Akin-Klemsa-Onen use a summed ring key with a concatenated LWE key and joint precomputation for a fixed party set, while bootstrapping remains linear in $N$, a different tradeoff point. Other compact schemes rely on interactive key generation, user-generated key-switching material per joint key, or two non-colluding servers. This paper's key aggregation uses only already-published material and a participating set chosen strictly after encryption, which is the harder setting MKFHE was originally defined for.

Open problems explicitly flagged by the authors:

  • Shrinking public material. In the indexed variants, each user must publish $N(n-1)\log q$ (fields) or $N\log q$ (rings) compression/relinearization entries, quadratic in $N$ overall even though the working material after aggregation is linear. AG26 achieves $\mathrm{poly}(\lambda)$ keys at the cost of $\mathrm{poly}(N)$ per-gate cost; this paper does the opposite. Achieving both simultaneously (small keys and $N$-independent per-gate cost) is identified as the natural next target.
  • Multi-hop preparation. Prepared wires are closed under the gate algorithms but not under the arrival of a new user: adding a party to an already-prepared wire requires returning to the original (unprepared) inputs. A multi-hop version of preparation that avoids this is left open.
  • Malicious key generation. The security analysis assumes honestly generated keys; a treatment surviving maliciously generated keys is left open.

# --- Column compression over fields (Section 4.1) ---
# Public: masks a[j,k,alpha] in Z_q^(n-1), for j in [N], k in [n-1], alpha in [0, log q)
# User i publishes (as part of PK_i):
#   w[i,j,k,alpha] =  + delta(i,j) * 2^alpha * s[i,k] + eps[i,j,k,alpha]

function KeyAgg_Compression(public_keys):
    for j in [N], k in [n-1], alpha in [0, log q):
        W[j,k,alpha] = sum_i w[i,j,k,alpha]      # O(N^2 n log q) additions
    return CK = (W[j,k,alpha])

function Compress(c):                             # c in Z_q^{nN}, blocks c_j in Z_q^n
    u_part = 0_{n-1}
    v_part = sum_j c[j,n]
    for j in [N], k in [n-1]:
        beta = g_inverse(c[j,k])                 # binary digits, length log q
        for alpha in range(log q):
            u_part -= beta[alpha] * a[j,k,alpha]
            v_part -= beta[alpha] * W[j,k,alpha]
    return (u_part, v_part)                       # in Z_q^n, phase ~= that of hat(t)^T c

# --- GSW-based MKFHE (Construction 4.2) ---

    return PP = (q, n, m, chi, B, d, N, chi_cmp, B_cmp, a[*])

function KeyGen(PP, i):
    sample s_i <- Z_q^{n-1}, e_i <- chi^m
    for j,k,alpha: sample eps[i,j,k,alpha] <- chi_cmp
    b_i = B^T s_i + e_i
    pk_i = A_i = [B ; b_i^T]            # MW public key
    sk_i = t_i = (-s_i^T, 1)^T
    for j,k,alpha:
        w[i,j,k,alpha] =  + delta(i,j) * 2^alpha * s_i[k] + eps[i,j,k,alpha]
    return PK_i = (i, pk_i, w[i,*,*,*]), SK_i = (i, t_i)

In addition to these main-body constructions, Appendix C gives a generic transformation (Construction C.1) from indexed to unindexed MKFHE, summarized as pseudocode below.


# --- Removing user indices (Appendix C, Construction C.1) ---
# Given: indMKFHE, an indexed MKFHE scheme; PKE, a semantically secure encryption
# scheme whose decryption circuit D_{ct*}(s) = PKE.Dec(s, ct*) is supported.

function Setup(lambda, d, N):
    D = depth bound for (PKE decryption) followed by (depth-d evaluation)
    pp = indMKFHE.Setup(lambda, D, N)
    return PP = (pp, d, N)

function KeyGen(PP):
    (pk_star, s_star) = PKE.KeyGen(lambda)
    for ell in [N]:
        (pk_ell, sk_ell) = indMKFHE.KeyGen(pp, ell)
        bk_ell = indMKFHE.Enc(pp, pk_ell, s_star)     # encrypt source secret under every candidate key
    return PK = (pk_star, {(pk_ell, bk_ell)}), SK = {sk_ell}

function Enc(PP, PK, mu):
    return PKE.Enc(pk_star, mu)

function KeyAgg(PP, {PK_i}):
    # canonical ordering assigns position i to user i
    (prep, eval) = indMKFHE.KeyAgg(pp, {pk_i^(i)})
    for i in [N]:
        hat_bk_i = indMKFHE.CTPrep(pp, prep, bk_i^(i))
    return PrepKey = ({hat_bk_i}, eval), EvalKey = eval

function CTPrep(PP, PrepKey, (i, CT)):
    ct_star = CT
    return indMKFHE.Eval(pp, eval, D_{ct_star}, hat_bk_i)   # homomorphically decrypt ct_star

function Eval(PP, EvalKey, C, {CT_prep_i}):
    return indMKFHE.Eval(pp, EvalKey, C, {CT_prep_i})

function Dec(PP, {SK_i}, CT_C):
    return indMKFHE.Dec(pp, {sk_i^(i)}, CT_C)
