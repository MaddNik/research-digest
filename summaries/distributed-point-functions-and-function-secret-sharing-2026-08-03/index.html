Distributed Point Functions and Function Secret Sharing

arXiv (cs.CR), preprint 2607.27696, submitted 30 July 2026 · full view ↗

Scope and Core Idea

This is a survey of distributed point functions (DPF) and their generalization, function secret sharing (FSS), covering definitions, constructions, applications and open problems. The authors state the article was written as of February 2026.

The starting point is ordinary additive secret sharing over a finite Abelian group $G$: a secret $s \in G$ splits into $(s_0, s_1)$ with $s_0 + s_1 = s$, and extended coordinatewise a vector $\mathbf{s} \in G^N$ splits into $(\mathbf{s}_0, \mathbf{s}_1)$. With perfect hiding this is optimal: each share must be uniform, so nothing can be compressed, and any pair of shares of a general $\mathbf{s}$ needs at least $N \lceil \log |G| \rceil$ bits in total. Assuming a pseudorandom generator (PRG) $G$ that stretches a $\lambda$-bit seed to a pseudorandom element of $G^N$ with $\lambda \ll N$, one may split $\mathbf{s}$ as $(r,\; \mathbf{s} - G(r))$; that shrinks one share but yields at most a $2\times$ reduction in total size, since the two shares together must still determine $\mathbf{s}$.

The escape is to restrict $\mathbf{s}$ to a class with short descriptions. If $s_x = f(x)$ for an efficiently computable $f$ whose description is much smaller than $\mathbf{s}$, one may hope to split $f$ into compressed shares $f_0, f_1$ with $f(x) = f_0(x) + f_1(x)$ for all $x$, where each $f_i$ alone computationally hides $f$ within the class. That is FSS. The extreme sparse case, a vector with at most one nonzero entry, is the DPF and is the survey's main focus.

Viewing $N = 2^n$, a maximally sparse $\mathbf{s} \in G^N$ is the truth table of a point function $f_{\alpha,\beta} : \{0,1\}^n \to G$:

$$f_{\alpha,\beta}(x) = \begin{cases} \beta & \text{if } x = \alpha \\ 0 & \text{if } x \neq \alpha. \end{cases}$$

A DPF represents additive shares of $f_{\alpha,\beta}$ by keys $(k_0,k_1) \leftarrow \mathsf{Gen}(1^\lambda, \alpha, \beta)$ with random access via $\mathsf{Eval}(i, k_i, x)$, so:

$$\mathsf{Eval}(0,k_0,x) + \mathsf{Eval}(1,k_1,x) = f_{\alpha,\beta}(x)$$

and a single key $k_i$ is computationally indistinguishable across any two choices $(\alpha,\beta)$, $(\alpha',\beta')$. In practice $\lambda = 128$.

Key-size bounds. Additively sharing the truth table gives a perfectly secure DPF with $N = 2^n$ group elements per key. Significantly beating this is impossible information-theoretically, and in the computational setting any nontrivial improvement implies a PRG. Conversely a PRG suffices for exponential compression: the best known construction has keys of size roughly $n \cdot \lambda + \log |G|$ bits.

Motivating Application: PIR by Keywords

Two servers $S_0, S_1$ each hold the same database $D$ of keywords $x_j \in \{0,1\}^n$ (for instance hashes of breached passwords). A client holding a search word $\alpha$ wants to learn whether $\alpha \in D$ without revealing $\alpha$ and with low communication. The client treats its query as $f_{\alpha,\beta} : \{0,1\}^n \to \mathbb{Z}_2$ with $\beta = 1$, runs $\mathsf{Gen}$, and sends $k_i$ to $S_i$. Each server returns the single bit

$$y_i = \sum_{x_j \in D} \mathsf{Eval}(i, k_i, x_j) \in \mathbb{Z}_2,$$

and the client concludes $\alpha \in D$ iff $y_0 + y_1 = 1$.

The example isolates two features the survey returns to repeatedly. First, additive output shares let a server aggregate over many inputs $x_j$ locally. Second, random access via $\mathsf{Eval}$ matters: for large $n$, anything scaling with the domain size $N = 2^n$ would be infeasible.

Formal Definitions

FSS syntax (Definition 2.1). A 2-party FSS scheme is a pair $(\mathsf{Gen}, \mathsf{Eval})$ where $\mathsf{Gen}(1^\lambda, f)$ is PPT and outputs $(k_0,k_1)$ for $f \in \{0,1\}^*$ (with $f$ explicitly containing descriptions of $G_{\mathrm{in}}, G_{\mathrm{out}}$ for $f : G_{\mathrm{in}} \to G_{\mathrm{out}}$), and $\mathsf{Eval}(i, k_i, x)$ is polynomial time and outputs $y_i \in G_{\mathrm{out}}$.

Correctness and security (Definition 2.2). For a class $\mathcal{F}$ and leakage function $\mathsf{Leak}$ (by default revealing only $G_{\mathrm{in}}, G_{\mathrm{out}}$):

$$\Pr\left[\mathsf{Eval}(0,k_0,x) + \mathsf{Eval}(1,k_1,x) = f(x)\right] = 1$$

for all $f \in \mathcal{F}$ and all $x \in G_{\mathrm{in}}$; and for each $i$ there is a PPT simulator $\mathsf{Sim}_i$ such that for every sequence $(f_\lambda)_{\lambda \in \mathbb{N}}$ of polynomial-size descriptions from $\mathcal{F}$, the following are computationally indistinguishable:

Real_lambda:  (k_0, k_1) <- Gen(1^lambda, f_lambda);  output k_i
Ideal_lambda: output Sim_i(1^lambda, Leak(f_lambda))

Simulation vs. indistinguishability. The original FSS definition was an indistinguishability (semantic-security) notion: $k_i$ generated from $f_\lambda$ is indistinguishable from $k_i$ generated from $f'_\lambda$. The two flavors are equivalent whenever $\mathsf{Leak}$ is efficiently invertible, i.e. given $\mathsf{Leak}(f)$ one can efficiently find $f' \in \mathcal{F}$ with $\mathsf{Leak}(f') = \mathsf{Leak}(f)$: the simulator picks such an $f'$, honestly runs $\mathsf{Gen}$, and outputs $k'_i$. The converse direction is immediate. Such an inversion algorithm exists for every class considered in the survey and essentially all from the literature.

Post-quantum security. The survey focuses on classical security, but notes that almost all constructions discussed are plausibly post-quantum secure, the exception being the group-based FSS schemes.

DPF (Definitions 2.3, 2.4). A point function $f_{\alpha,\beta}$ for $\alpha \in \{0,1\}^n$, $\beta \in G$ has $f(\alpha) = \beta$ and $f(x) = 0$ elsewhere. A DPF is the corresponding FSS instance, with $\mathsf{Gen}(1^\lambda, f_{\alpha,\beta})$ and $\mathsf{Eval}(i,k_i,x)$, perfect correctness, and simulation security where $\mathsf{Sim}$ receives only $(1^n, G)$.

Additional syntax. Two extra algorithms appear throughout the applications:

  • $\mathsf{DistGen}(1^\lambda, f_{\alpha,\beta})$: a distributed key-generation protocol securely realizing the functionality that takes shares of $\alpha, \beta$ from $P_0, P_1$, evaluates $\mathsf{Gen}$, and hands $k_i$ to $P_i$. Needed when $\alpha$ and/or $\beta$ are themselves secret shared, e.g. when jointly generating PCG seeds or in secure computation of RAM programs.
  • $\mathsf{FullEval}(i, k_i)$: outputs the whole vector $(y_i^x)_{x \in \{0,1\}^n}$ with $y_0^x + y_1^x = f(x)$. Feasible only for polynomial-size domains. For the tree-based DPF it expands the tree once at cost $O(N)$ PRG calls plus $O(N)$ output writes, using $O(N)$ memory if all leaves are materialized or small working memory if leaves are streamed, versus $O(N \log N)$ for $N$ separate $\mathsf{Eval}$ calls.

Extensions considered and excluded. FSS generalizes to $m \geq 2$ parties with $t < m$ corruptions, where any $t$ keys must reveal nothing beyond $\mathsf{Leak}(f)$. One can also relax additive reconstruction: linearity is what gives the compressibility used everywhere (e.g. $\sum_{x \in S} \mathsf{Eval}(i,k_i,x)$ are automatically shares of $\sum_{x \in S} f(x)$) and forces output shares to live in the output space, so share succinctness is free. A natural relaxation only requires the $\mathsf{Eval}$ output length to depend on the output length of $f$ rather than its input length. This survey considers only additive reconstruction.

Variants: DCF, DMPF, Multiplicative DPF

Distributed comparison function (DCF). FSS for $f^{<}_{\alpha,\beta} : \{0,1\}^n \to G$ with $f^{<}_{\alpha,\beta}(x) = \beta$ for $x < \alpha$ and $0$ for $x \geq \alpha$, ordering $\{0,1\}^n$ as integers ($0^n$ smallest, $1^n$ largest).

Distributed multi-point function (DMPF). For $A = \{\alpha_1, \dots, \alpha_t\} \subset \{0,1\}^n$ in ascending order and $B = (\beta_1, \dots, \beta_t) \in G^t$, the $t$-point function $f_{A,B} : \{0,1\}^n \to G$ evaluates to $\beta_i$ at $\alpha_i$ and $0$ elsewhere. A DMPF is FSS for the collection of all $t$-point functions with leakage $\mathsf{Leak}(f_{A,B}) = (1^n, G, t)$: keys may reveal the weight bound $t$ and the complexity may grow with $t$.

Multiplicative DPF. In an $(m,t)$-multiplicative DPF the output group is the additive group of a commutative ring $R$ and $\mathsf{Eval}$ outputs an $(m,t)$-multiplicative secret sharing of $f_{\alpha,\beta}(x)$. Any $t$ keys reveal nothing beyond the leakage. Parties can then locally compute any polynomial of degree at most $\lfloor (m-1)/t \rfloor$ in the shared DPF outputs; for $t = 1$ this degree is $m-1$.

Two-Party Constructions: Warmup and Square-Root DPF

All constructions rest on two building blocks: additive secret sharing over $\mathbb{Z}_2^{\ell}$, written $[s] = (s_0, s_1)$ with $s = s_0 \oplus s_1$, and a PRG $G$ stretching a $\lambda$-bit seed to length $\ell(\lambda) \gg \lambda$. Two homomorphisms of additive sharing are used:

  1. Linear homomorphism. $A \cdot [s] = (A s_0, A s_1)$ shares $As$. The useful corollary is the conditional correction gadget: given $[s]$, a shared control bit $[t]$ and a public correction word $CW \in \{0,1\}^{\ell}$, the parties can locally compute $[s']$ for $s' = s + t \cdot CW$, correcting $s$ by $CW$ exactly when $t = 1$.
  2. PRG-based weak homomorphism (2-party only). $G([s]) = (G(s_0), G(s_1))$ maps shares of $s = 0^\lambda$ to shares of $0^{\ell}$, and shares of a random $s$ to shares of a longer string $s'$ that is pseudorandom even given one share of $s$.

Because the second homomorphism is specific to two parties, the best known DPF constructions do not extend beyond two parties.

Square-root DPF. Take domain $[N]$ with $N = \ell^2$ and output group $\mathbb{Z}_2$, and fold the target vector $\mathbf{u}$ (with $u_\alpha = \beta$) into an $\ell \times \ell$ matrix $M$; $\alpha$ lies in a unique row $i$, all other rows are zero. Step one generates compressed shares of a related matrix $M'$ that agrees with $M$ except that row $i$ is pseudorandom: sample an independent seed $s^j$ for each row $j \neq i$ shared by both keys, and two independent seeds $s^i_0, s^i_1$ for row $i$. Expanding each row with the PRG yields $[M']$, since equal seeds cancel under XOR. Step two corrects row $i$ using the conditional correction gadget with a shared control bit per row (1 for row $i$, 0 elsewhere) and public

$$CW = G(s^i_0) \oplus G(s^i_1) \oplus (0, \dots, \beta, \dots, 0).$$

Each augmented key holds $(\lambda + 1)\ell$ secret bits plus an $\ell$-bit public correction, so key size is $O(\sqrt{N})$. This construction is implicit in the two-server PIR scheme of Chor and Gilboa. Observing that the two keys are identical except in the length-$\lambda$ part for row $i$, the non-public part is itself an additively shared point function over $G = \mathbb{Z}_2^{\lambda}$, which suggests recursion and motivates the tree-based approach.

Two-Party Constructions: Tree-Based DPF

Theorem 3.1. If $G : \{0,1\}^\lambda \to \{0,1\}^{2(\lambda+1)}$ is a PRG, then the scheme $(\mathsf{Gen}^\bullet, \mathsf{Eval}^\bullet)$ is a DPF for $f_{\alpha,\beta} : \{0,1\}^n \to G$ with key size

$$n \cdot (\lambda + 2) + \lambda + \lceil \log_2 |G| \rceil \text{ bits}.$$

The number of PRG invocations is at most $2\left(n + \left\lceil \frac{\log |G|}{\lambda+2} \right\rceil\right)$ in $\mathsf{Gen}$ and at most $n + \left\lceil \frac{\log |G|}{\lambda+2} \right\rceil$ in $\mathsf{Eval}$.

Structure. Each key defines a GGM-style binary tree with $2^n$ leaves labeled by inputs $x \in \{0,1\}^n$. The root-to-leaf path of $x$ is its evaluation path; the path of $\alpha$ is the special path. Each node carries a label of $\lambda + 1$ bits, a control bit $t$ and a $\lambda$-bit seed $s$, fully determined by its parent's label. $\mathsf{Eval}^\bullet$ walks the path to $x$ from the root label in the key and outputs the leaf control bit (for single-bit $\beta = 1$).

Invariant. For every node off the special path the two parties' labels are identical; for every node on the special path the two control bits differ and the two seeds look random and independent. Since a node's label is determined by its parent, the invariant propagates automatically once a node is off the special path. It holds at the root because the root labels are given explicitly in the keys. The only work is preserving it when leaving the special path.

Per-level step. Viewing the labels as shares $[t] = (t_0,t_1)$, $[s] = (s_0,s_1)$, both parties locally compute $[S] = G([s])$ for $G : \{0,1\}^\lambda \to \{0,1\}^{2\lambda+2}$ and parse $[S] = [s^L, t^L, s^R, t^R]$, the first pair for the left child and the second for the right. Only nodes on the special path need correcting, where the invariant gives $t = 1$ so the correction applies. Suppose $\alpha_i = 1$, so the left child leaves the special path and the right child stays on it. Including in both keys

$$CW^{(i)} = (s^L,\; t^L,\; s^R \oplus s',\; t^R \oplus 1)$$

for a random $s'$ leaves the children's labels at $[0],[0]$ and $[s'],[1]$ as required. Since $s'$ only needs to be pseudorandom, one can instead use the $(\lambda+2)$-bit correction

$$CW^{(i)} = (s^L,\; t^L,\; s^L,\; t^R \oplus 1),$$

which corresponds to $s' = s^L \oplus s^R$. $\mathsf{Gen}^\bullet$ computes the $n$ values $CW^{(i)}$ iteratively along the special path from the root labels and puts them in both keys. For $\beta = 1$ the output of $\mathsf{Eval}^\bullet$ is just the leaf control-bit share; a general $\beta$ in an arbitrary Abelian group is handled by one extra correction $CW^{(n+1)}$. Full pseudocode is in the Algorithms appendix.

Multi-Party DPF

An $(m,t)$-DPF has a dealer distributing keys to $m$ parties with $1 \leq t < m$ corruptions. Three regimes are known.

Regime $t = 1$. Performance roughly matches the two-party tree scheme, and the output is multiplicatively shared, allowing low-multiplicative-depth circuits over the output without interaction.

Theorem 3.2 (multiplicative $(m,1)$-DPF). For a PRG with seed length $\lambda$, group $G$ and $m > 2$, there is an $(m,1)$-DPF for $f_{\alpha,\beta} : \{0,1\}^n \to G$ whose output is CNF secret shared over $G$ with threshold 1 and whose key size per party is

$$O\!\left(m n (\lambda + \log m) + m^2 \log |G|\right).$$

For additive reconstruction $G$ need only be Abelian; for local multiplication (e.g. after conversion of CNF shares into Shamir shares) $G$ should be viewed as the additive group of a commutative ring, with local products taken in that ring. If $G$ is a field $\mathbb{F}$ with $|\mathbb{F}| > m$, CNF shares can be locally converted to Shamir shares and polynomials of degree at most $m-1$ evaluated.

The realizing scheme follows the two-party tree structure with two differences: each level carries roughly $m$ correction words, and each node holds both a PRG seed and the ID of one correction word. Off-path nodes have identical seeds and IDs across all $m$ parties; on-path nodes have independent pseudorandom seeds and pairwise distinct IDs. Maintaining this to the leaves and stretching the final seeds to $m-1$ group elements yields replicated (CNF) shares of $\beta$ at $\alpha$ and of $0$ elsewhere.

Regime $t = m-1$ (full threshold). Here two-party tricks break down: encoding a zero bit by identical seeds fails because an adversary controlling two or more parties can detect that they share a zero bit. The best known OWF-based schemes achieve only square-root behavior.

Theorem 3.3. For a PRG $G : \{0,1\}^\lambda \to \{0,1\}^{2\lambda}$, $G = \mathbb{F}_2$ and $m > 2$, there is an $(m, m-1)$-DPF with additive output sharing and key size per party

$$2^{\lceil n/2 \rceil} \cdot 2^{\lceil (m-2)/2 \rceil} \lambda (1 + o(1)).$$

The domain $\{0,1\}^n$ is again viewed as a near-square matrix with a critical row $\alpha_1$ and column $\alpha_2$. The scheme samples $2^{m-1}$ independent seeds per row: in non-critical rows, one seed $s_S$ per even-size subset $S \subseteq [m]$, given to all $i \in S$; in the critical row, one fresh seed $s_{S'}$ per odd-size subset. $\mathsf{Eval}$ expands every seed to row length; over $\mathbb{F}_2$ the sum is $0$ in non-critical rows and some pseudorandom $v$ in the critical row. A correction word $cw$ satisfies $v \oplus cw = e_{\alpha_2}$, and additive shares of a per-row control bit (1 in $\alpha_1$, else 0) gate its application. Security rests on two facts: given $m-1$ parties, the seed distribution looks the same for the critical and non-critical rows; and the honest party holds one seed no other party has, so $cw = v \oplus e_{\alpha_2}$ is computationally indistinguishable from random to the adversary. The survey's presentation uses a single correction word instead of $2^{m-1}$, which via careful balancing of rows and columns reduces the key-size dependence on $m$ from about $2^m$ to roughly $2^{m/2}$.

Remark 3.4. The output group generalizes to $\mathbb{Z}_p$ for small prime $p$ at a multiplicative cost $O\!\left((p/2)^{m/2}\right)$ in key size; generalization to $\mathbb{Z}_k$ for smooth $k$ with distinct prime factors follows from the Chinese Remainder Theorem.

Theorem 3.5. For a PRG $G : \{0,1\}^\lambda \to \{0,1\}^{2\lambda}$, $G = \mathbb{Z}_{pq}$ with $p$ prime and $q$ an integer, and $m > 2$, there is an $(m, m-1)$-DPF with additive output sharing and key size per party $\mathrm{poly}(m,\lambda) \cdot 2^{n/2}$.

This work first shows any deterministic seed-distribution pattern satisfying three properties must be exponentially large: (1) each seed in a non-critical row is used an even number of times across all parties, (2) each party gets a unique seed for the critical row, and (3) the seed distribution is identical between critical and non-critical rows. Hence the earlier pattern is optimal under those properties. A randomized pattern escapes: $\mathsf{Gen}$ hands the same seed to $a$ random pairs of parties (allowing a pair of seeds to the same party) per row, plus $b$ extra seeds, one per party, in the critical row. This satisfies properties (1) and (2), and for careful $a, b$ the statistical distance between critical and non-critical row distributions is inverse-polynomial (not negligible). A local privacy-amplification step via locally decodable codes then drives the distinguishing advantage to negligible. Correction words and control bits are inherited unchanged and do not affect the asymptotic key size.

Regime $m = td + 1$, $d > 1$ (gapped threshold).

Theorem 3.6. For a PRG $G : \{0,1\}^\lambda \to \{0,1\}^{2\lambda}$, $G = \mathbb{F}_2$, $d, t > 1$ and $m = dt + 1$, there is an $(m,t)$-DPF with additive output sharing and key size per party

$$O\!\left(2^{n/2d} \cdot 2^{mt/2} \cdot m t d \lambda\right).$$

The domain is viewed as a $d$-dimensional cube of side $2^{n/d}$; for $\alpha = (\alpha_1, \dots, \alpha_d)$ the goal is to compute $f_{\alpha_1,\beta} \cdot \prod_{i=2}^{d} f_{\alpha_i,1}$. Let $(\mathsf{Gen}', \mathsf{Eval}')$ be a DPF for $m' = \binom{m}{t}$ parties with threshold $t' = m' - 1$. Each virtual party corresponds to a size-$t$ subset of real parties, and a real party receives all keys of subsets it does not belong to, so any $t$ real parties miss one key. $\mathsf{Eval}$ first runs $\mathsf{Eval}'$ on each coordinate $x_i$, giving $(m',d)$ CNF shares of each $f_{\alpha_i,\cdot}(x_i)$, then uses multiplicativity of CNF sharing to non-interactively obtain additive shares of the product, which is $\beta$ if $x = \alpha$ and $0$ otherwise.

From DPF to DCF

Any DPF yields a DCF with multiplicative overhead $n$. Note $x < \alpha$ iff exactly one of $n$ mutually exclusive conditions holds: $x_1 < \alpha_1$; or $x_1 = \alpha_1$ and $x_2 < \alpha_2$; and so on. Rewriting condition $i$ as $x_1 x_2 \cdots x_{i} \equiv \alpha_1 \alpha_2 \cdots \alpha_{i-1} 0 \alpha_i$ and using mutual exclusivity gives

$$f^{<}_{\alpha,\beta}(x) = \sum_{i=1}^{n} f_{\alpha^i, \beta}(x^i) \tag{1}$$

with $\alpha^i = \alpha_1 \alpha_2 \cdots \alpha_{i-1} 0 \alpha_i$ and $x^i = x_1 x_2 \cdots x_i 1$, reducing DCF to $n$ DPF instances.

The tree-based DPF does much better. In the useful case $G = \mathbb{Z}_2$, $\beta = 1$, the same DPF key for $f_{\alpha,\beta}$ already serves as a DCF key for $f^{<}_{\alpha,\beta}$: the tree construction implicitly produces additive shares of $f_{\alpha',\beta}$ for every prefix $\alpha'$ of $\alpha$, so each term of Equation 1 is locally computable. If $x_i = 1$ the term is $0$ and can be dropped; if $x_i = 0$ the term equals $f_{\alpha',\beta}(x_1 \cdots x_{i-1} 1)$ where $\alpha'$ is the length-$i$ prefix of $\alpha$. For general $G$ and $\beta$ it suffices to augment the tree so every intermediate level is also treated as a final output level, producing the required prefix-DPF instances at a cost of roughly $n \log |G|$ extra correction bits per key. Two DCF instances give a distributed interval function, evaluating to $\beta$ on a secret interval $[a,b]$ and $0$ elsewhere.

From DPF to DMPF

Four approaches, each dominant in some parameter range:

  • Naive DMPF. Sum $t$ independent weight-1 DPFs: cost $\times t$ in all metrics.
  • Big-state DMPF. Generalize the tree's indicator bit to an indicator $t$-bit string, maintaining the invariant that a node on the $k$-th accepting path at depth $i$ carries the one-hot encoding $e_k = 0^{k-1} \Vert 1 \Vert 0^{t-k} \in \{0,1\}^t$. This lets the parties unknowingly apply different conditional corrections for $t$ positions per layer. Each level holds $t$ sets of correction words of $\lambda + 2t$ bits each; at each node and for each $\ell \in [t]$ a party conditionally XORs in the $\ell$-th correction word based on the $\ell$-th bit of its local indicator string. Costs grow quadratically in $t$, but this typically wins on full-domain evaluation for $3 \leq t \leq 70$.
  • DMPF from probabilistic batch codes (PBC). A batch code distributes a database over $\ell$ servers so that any batch of $t$ symbols is retrievable by reading one symbol per server, minimizing total storage using $\ell > t$ servers. Probabilistic variants replicate each symbol among a set of servers via a probabilistic pattern and can be built from cuckoo hashing. Applied to DMPF, a PBC reduces a weight-$t$ DMPF on domain $N = 2^n$ to $\ell > t$ separate weight-1 DPFs of domain $< N$, with a mapping such that every one of the $N$ positions is covered at least once and, for any $t$ positions in the length-$N$ vector, at most one entry from each of the $\ell$ vectors suffices to cover them. Key size scales with $\ell$ and full evaluation time with total storage, which can approach $2N$ for cuckoo-hashing-based PBC.
  • OKVS-based DMPF. Oblivious key-value stores, originally for private set intersection, encode positions in the binary tree (keys) paired with correction information (values), and these encodings go in the DMPF keys. An OKVS abstracts and generalizes polynomial interpolation with higher concrete efficiency. A simple polynomial-based OKVS already improves on naive DMPF; the "random bands" RB-OKVS construction yields the fastest evaluation time over a wide range of practical parameters.

Regime comparison (experimental, minimal $\mathsf{FullEval}$ time, largely independent of $N = 2^n$):

  • Naive DMPF: $t \leq 2$
  • Big-state DMPF: $3 \leq t \leq 70$
  • OKVS-based DMPF: $70 < t < 10^4$
  • PBC-based DMPF: comparable to OKVS from $t \geq 10^4$, best from around $t \approx 21{,}000$

For single-evaluation $\mathsf{Eval}$ the picture is similar but the big-state-to-OKVS switch happens near $t = 9$ rather than $t = 70$. Each dominant regime matters in practice: big-state DMPF suits state-of-the-art PCG implementations and other small-$t$ uses, while OKVS- and PBC-based DMPF improve unbalanced PSI in the two-server model, where a client intersects its $t$ keywords (each $n$ bits) with a large or streaming keyword set held by two remote servers.

Information-Theoretic DPF

Nontrivial $m$-party DPFs exist even information-theoretically, where any $t$ keys perfectly hide the point function, provided $t < m/2$. These are closely tied to information-theoretic PIR. The first generation of such PIR schemes was based on Reed-Muller codes with communication $N^{1/\Theta(m)}$, and for $m \geq 3$ they imply DPFs of similar key size.

Theorem 3.7 (Reed-Muller DPF). For prime $p \geq 2$ and integer $m \geq 2$ there is a perfectly secure $m$-party DPF for point functions with domain $[N]$ and output group $\mathbb{Z}_p$, with key size

$$O\!\left(m \log m \log(p) \cdot N^{1/(m-1)}\right).$$

This extends to thresholds $t \geq 2$ by scaling $m$ by roughly a factor of $t$.

Later information-theoretic PIR schemes reached $N^{o(1)}$ communication with as few as two servers. In those two-server schemes the servers output additive shares of a length-$N^{o(1)}$ vector whose inner product with a secret combination vector known to the client yields the answer. Doubling the number of servers so each answer is known to two servers, and sharing the client's combination vector between each pair, gives a 4-server PIR scheme with additive reconstruction, hence:

Theorem 3.8 (perfectly secure 4-party DPF). For prime $p \geq 3$ and $s \geq 1$ there is a perfectly secure 4-party DPF ($t = 1$) with output group $\mathbb{Z}_{p^s}$, domain size $N$, and key size

$$O\!\left(s \log(p) \cdot 2^{\,2\sqrt{p \log N \log \log N}}\right).$$

Three parties are more delicate, and only statistical security is known. The starting point is a relaxed 3-party DPF derived from 3-server PIR in which the nonzero value $\beta$ cannot be fully controlled and inherently depends on $\alpha$; revealing a correction mapping the shared $\hat\beta$ to the target $\beta$ would leak $\alpha$. The fix modifies the relaxed DPF so the $\beta$ values retain at least one bit of entropy even conditioned on $\alpha$, applies $O(\sigma)$ independent copies to get $O(\sigma)$ bits of entropy, and maps the random $\hat\beta$ to $\beta$ with a compressive linear hash function published in all three keys. Statistical security follows from the Leftover Hash Lemma.

Theorem 3.9 (statistically secure 3-party DPF). There is a statistically $2^{-\sigma}$-secure 3-party DPF for point functions with output group $\mathbb{Z}_p$ (prime $p$), domain size $N$, and key size

$$O\!\left(\sigma \log(p) \cdot 2^{\,k(p)\sqrt{\log N \log \log N}}\right),$$

where $k(2) = 6$, $k(3) = 10$, and $k(p) = 2p$ for $p \geq 5$. Extensions to more general output groups are known.

State of the Art in FSS Constructions, by Assumption

Complexity measures are for $n$-bit inputs, and results are for $m = 2$ parties unless stated otherwise.

Lowest end: information-theoretic FSS. Perfectly secure $m$-party FSS for linear functions is just additive secret sharing. Secret-sharing the truth table works for an arbitrary class $\{f : \{0,1\}^n \to G\}$ but needs key size $2^n \log |G|$. A third perfect construction covers secret linear combinations of public functions,

$$f_{\vec\alpha}(x) = \sum_{i \in S} \alpha_i g_i(x),$$

where $\{g_i : \{0,1\}^n \to G\}_{i \in S}$ are public for a module $G$ over a ring $R$ and $\vec\alpha = (\alpha_i)_{i \in S}$ are secret $R$-coefficients. Additively sharing the $\alpha_i$ gives perfectly secure $m$-party FSS with key size $|S| \lceil \log |R| \rceil$: each party computes $g_i(x)$ in the clear and outputs the combination dictated by its shares. Taking the $g_i$ to be all monomials up to a given degree yields FSS for low-degree multivariate polynomials. Richer information-theoretic schemes exist for $m > 2$ with $t < m/2$.

Low end: FSS from one-way functions. A PRG (equivalently a OWF) suffices for the simple classes that are the survey's focus, and this assumption is minimal for $m = 2$ with nontrivial classes and key size. The constructions use a PRG stretching $\lambda$ bits to roughly $2\lambda$ in a black-box way; AES-based implementations take $\lambda = 128$.

  • Point functions. The first nontrivial two-party DPF (implicit in computationally private PIR) had key size $2^{O(\sqrt{n})} \cdot \lambda$, superpolynomially better than the naive $2^n$ truth-table sharing though not polynomial in $n$. The explicit notion came with a recursive construction of key size $O(n^{\log_2 3} \cdot \lambda)$, improved to $O(n\lambda)$ by a tree-based construction. The best to date is the 2016 Boyle-Gilboa-Ishai scheme with key size $\approx n\lambda + |\beta|$, precisely $\lambda + n(\lambda + 2) - \lfloor \log(\lambda/|\beta|) \rfloor$ bits, i.e. $\lambda + n(\lambda+2)$ for $\lambda$-bit outputs and $\lambda + n(\lambda+2) - \lfloor \log \lambda \rfloor$ for 1-bit outputs. Any nontrivial improvement is a highly motivated open problem.
  • Multi-party DPF. For $t = m-1$, key size $O(2^m 2^{n/2} \lambda)$, with the dependence on $m$ improved from exponential to polynomial, i.e. $2^{n/2}\,\mathrm{poly}(\lambda,m)$, by the randomized design (though for small $m$ the earlier scheme has better concrete efficiency). Beating the square-root bound from symmetric cryptography alone is a central open question; it is open even whether a OWF implies a 3-server DPF secure against 2 corruptions with key size $O(\lambda \cdot 2^{(1/2-\epsilon)n})$ for constant $\epsilon > 0$. For a threshold gap $1 \leq t < m-1$, better constructions come from information-theoretic PIR or from PRG-based DPF, and one can get multiplicative DPF where parties locally convert outputs to additive shares of a product of up to $\lfloor (m-1)/t \rfloor$ DPF outputs.
  • Comparison and interval functions. Comparison functions cost about as much as a DPF; interval functions roughly twice that.
  • Multi-point functions. DMPF extends many DPF applications; e.g. PIR by keywords becomes intersection of a client's $t$ keywords with a server database $D$, at communication linear in $t$ and logarithmic in $|D|$.
  • Offset function classes. Secure computation with preprocessing reduces secure evaluation of a gate $g : G_{\mathrm{in}} \to G_{\mathrm{out}}$ (shares in, shares out) to FSS for the offset class containing $g_r(x) = g(x - r)$ for every $r \in G_{\mathrm{in}}$. Many useful nonlinear gates induce FSS-friendly offset classes: for a zero-test gate outputting $1 \in \mathbb{Z}_2$ on zero input, the offset class is exactly the point functions with $0/1$ outputs. Optimized schemes exist for ReLU, splines (piecewise polynomials) and more.
  • $NC^0$ functions. For $d$-local $f : \{0,1\}^n \to \{0,1\}^k$ with $d = O(1)$, a PRG-based DPF gives FSS with key size $O_d(k \log n \cdot \lambda)$ and evaluation time scaling with $n^d$. The case $k = 1$ captures bit-matching predicates on a constant number of bits. This uses the fact that FSS for an arbitrary class of size $N$ reduces to a DPF of domain size $N$, sharing the indicator vector of the function within the class.
  • Decision trees with topology leakage. Key size roughly $|V| \cdot \lambda$ bits for node set $V$, with $|V|$ PRG invocations and a comparable number of additions per evaluation. Secret edge value labels and leaf output labels are hidden, but the base tree topology and which variable sits at each node are revealed.
  • Constant-dimensional intervals. FSS for $d$-dimensional intervals, nonzero exactly when $a_i \leq x_i \leq b_i$ for secret ranges, follows from the decision-tree scheme with key size and computation $O(n^d \cdot \lambda)$; $d = 2$ (rectangles) has reasonable concrete efficiency. A lower bound of $\tilde\Omega(n^{1.5})$ on evaluation time for 2-dimensional intervals with black-box PRG use was recently obtained via a connection with dynamic data structures.

In the PIR setting, FSS for these classes combines with server-side database operations to emulate private database search with richer queries such as Max/Min and top-$k$.

Homomorphic secret sharing. HSS is the dual: a public function on a secret-shared input, versus FSS's secret-shared function on a public input. They are related but not identical. HSS for $\mathcal{F}$ requires the share size of an input $x$ to grow only with $|x|$ while supporting homomorphic evaluation of every $f \in \mathcal{F}$, whereas FSS for $\mathcal{F}$ inherently has key size growing with the description size of $f$. FSS reduces generically to HSS via universal functions: if $U_{\mathcal{F}}(f,x) = f(x)$ for all $f \in \mathcal{F}$ and $x$, then FSS for $\mathcal{F}$ reduces to HSS for $U_{\mathcal{F}} := \{U_{\mathcal{F}}(\cdot, x) : x \in \{0,1\}^n\}$, with the resulting FSS key size inherently scaling with the description size of $f$.

Mid range: FSS/HSS from LPN-style assumptions. LPN asserts that solving a system of uniformly random linear equations over $\mathbb{F}_2$ is hard when each bit is flipped with small probability $\epsilon$; the search variant is equivalent to the decision variant that noisy linear combinations are pseudorandom, and equivalently that decoding a noisy random codeword from a random linear code is hard. Changing the equation distribution amounts to other linear codes, and many variants over other fields and noise/code distributions are standard. Depending on the noise rate, LPN sits between symmetric and public-key cryptography: low-noise LPN implies public-key encryption but is not known to imply additively homomorphic encryption, nor even collision-resistant hashing except in an extreme parameter regime. Known LPN-based HSS:

  • HSS for constant-degree polynomials from standard LPN.
  • HSS for degree $\log \lambda / \log \log \lambda$ polynomials from superpolynomial hardness of LPN.
  • Multi-party HSS for degree $\log \lambda / \log \log \lambda$ polynomials from a sparse variant of LPN, for any number of parties $m$ and any linear output sharing. Combined with linearly homomorphic encryption it yields a homomorphic encryption scheme for a similar class. Unlike earlier LPN-based HSS, it suffers inverse-polynomial error.
  • For the default additive-output notion, the error can be made negligible for constant-degree polynomials, which implies a multi-party DPF with key size scaling as $N^{1/d}$ for an arbitrary constant $d$; this relies on (non-sparse) LPN plus a flavor of the MQ assumption that a random system of quadratic equations is hard to solve, and also counts as mid-range since neither is known to imply public-key cryptography.

In all these the share size is linear in the input size and sublinear in the description size of the evaluated function, which rules out, for instance, HSS for constant-degree polynomials by additively sharing all monomials. An HSS scheme for degree-2 polynomials with compact but non-additive output shares exists from threshold additively homomorphic encryption, and compact non-additive HSS for low-degree polynomials from partially homomorphic encryption.

High end: FSS/HSS from public-key cryptography.

  • Branching programs, inverse-polynomial error. From Decisional Diffie-Hellman (DDH), with $\mathsf{Eval}$ running time $\tilde O(s^2/\delta)$ for branching program size $s$ and error $\delta$ (which can be made Las-Vegas detectable), improved to $\tilde O(s^{1.5}/\delta^{0.5})$. Optimized DDH-based variants exist for simple useful classes, and a similar construction is known from Decisional Composite Residuosity (DCR).
  • Branching programs, negligible error. From DCR, with running time linear in $s$.
  • Circuits. A general-purpose FSS/HSS scheme for Boolean circuits from Learning With Errors (LWE) via "spooky encryption", combining multi-key FHE with a local rounding procedure that converts noisy additive shares over a big modulus into almost noiseless additive shares over a small modulus. A more efficient LWE (and Ring-LWE) construction is known for branching programs, avoiding homomorphic multiplication of ciphertexts and instead emulating restricted multiplications via a form of distributed decryption. A more direct FSS for branching programs from LWE (and a small-exponent variant of DCR) bypasses the universal-circuit overhead of the HSS-to-FSS transformation.

Application: Efficient Distributed Key Generation

In many applications no single entity knows the secret point function; the client role is split across parties and $\mathsf{Gen}$ must run inside a secure protocol. This arises for secure computation of RAM programs, mixed-mode operations, and PCG seed generation. Generic secure computation of the $\mathsf{Gen}$ circuit works but requires unrolling the PRG into a Boolean circuit, which is undesirable. The alternative is a targeted protocol that stays black box in the PRG: parties evaluate the PRG locally on various inputs and never need its code or circuit.

The initiating work (Doerner and shelat, in the context of DPF-based secure computation of RAM programs) gives a distributed $\mathsf{Gen}$ for the tree-based DPF with computation linear in the domain size $N$ and $\log N$ sequential rounds, making only black-box use of oblivious transfer and a PRG. It remains the most efficient to date.

How it works. A tree-based DPF key consists of an initial seed sampled independently per party plus $n+1$ public correction words. The $i$-th word ensures the off-path child of the $i$-th on-path node has identical values in both trees while the on-path child stays pseudorandom, which is achieved by setting it to the XOR of the two values of the off-path child. Write $s_{0,\ell}, s_{1,\ell}$ for the left-child seeds and $s_{0,r}, s_{1,r}$ for the right. Expand all level-$i$ seeds to double length and split into left and right halves. The key observation: if all level-$i$ nodes agree across the two trees except $v$, then the XOR of all left halves is $L \oplus s_{0,\ell}$ for party 0 and $L \oplus s_{1,\ell}$ for party 1, for a common string $L$ depending only on off-path nodes, and similarly $R \oplus s_{0,r}$, $R \oplus s_{1,r}$ for right halves. So the $i$-th correction word is either the XOR of all left halves across both trees or the XOR of all right halves, and which one depends on $\alpha$.

Given bitwise shares of $\alpha$ and additive shares of $\beta$ in $G$, each party samples a random initial seed, and the parties compute correction words in order $1, \dots, n$. For word $i$, party 0 is the OT sender with messages $m_0 = L \oplus s_{0,\ell}$, $m_1 = R \oplus s_{0,r}$ if its share of $\alpha_i$ is 0, and the two swapped if its share is 1. Party 1 is the receiver with choice bit $b$ equal to its share of $\alpha_i$, and computes the correction word as $m_b \oplus (L \oplus s_{1,\ell})$ if $b = 0$ or $m_b \oplus (R \oplus s_{1,r})$ if $b = 1$, then shares it with party 0. The last correction word, which masks $\beta$, needs no OT: each party expands a seed to all leaves as elements of $G$ and a fixed linear combination of these values and of the $\beta$ shares gives $CW^{(n+1)}$. The protocol uses $O(2^n)$ PRG expansions and exactly $n$ string OTs. The procedure was extended to distributed comparison functions.

Round complexity. The $O(N)$ computation is not known to be avoidable without non-black-box use of cryptographic primitives. The $\log N$ rounds can sometimes be reduced: in relaxed settings where leaking $\alpha$ to one party is acceptable (but not $\beta$), all OTs run in parallel and two rounds suffice. Programmable DPF achieves constant rounds without leaking $\alpha$, but with poor concrete efficiency. For DMPF, distributed setup is more involved, especially for batch-code or OKVS constructions; a recent "reverse cuckoo hashing" DMPF simplifies setup by first picking a valid assignment and then solving a linear system inside 2-PC to determine the hash functions, instead of sampling hash functions and obliviously assigning items to bins.

Application: Private Reading

Beyond the keyword-membership PIR of the introduction, take a database $D$ of key-value pairs $(v_i, x_i)$. A sum query lets the client learn the sum over the DPF output group $G$ of all $x_i$ with $v_i = \alpha$: it generates keys for $f_{\alpha,1}$, each server $b$ computes

$$y_b = \sum_{(v_i,x_i) \in D} \mathsf{Eval}(b, k_b, v_i) \cdot x_i,$$

and the client reconstructs $y_0 + y_1$. Replacing DPF with DCF selects or sums values in a given interval. Various matching and aggregation functions of this type support private database queries covering a relatively large subset of SQL. This approach also yields simple and fast PIR implementations.

Unbalanced private set intersection. A client holding a small set $C$ wants $C \cap D$ for a server database $D = \{v_i\}$. Relaxing standard PSI to a two-server model with non-colluding servers, the parties run the naive PIR lookup for each $\alpha \in C$. Communication is independent of $|D|$, unlike standard PSI, which suits scenarios such as private contact discovery where the server set is far larger than the client's. A form of FSS has also been used for structure-aware PSI, where one party's set has publicly known structure, yielding fuzzy PSI and beyond.

Application: Private Writing, Aggregation, and Verifiability

Private writing. Two servers hold additive shares $v_{0,i}, v_{1,i}$ of each entry $v_i = v_{0,i} + v_{1,i}$ of $D$. A client updating entry $\alpha$ from $v_\alpha$ to $v'_\alpha$ creates DPF keys for $f_{\alpha,\beta}$ with $\beta = v'_\alpha - v_\alpha$; each server sets $v'_{b,i} = v_{b,i} + \mathsf{Eval}(k_b, i)$. It is inherent here that no single server may know the database, which is enforced by secret-sharing it.

Private aggregate statistics. For a private histogram over websites indexed by $S = [n]$, each client holds a private $\alpha_i \in S$ (e.g. the site that triggered a browser crash), generates DPF keys $(k_{i,0}, k_{i,1})$ for $f_{\alpha_i,1}$, and sends $k_{i,b}$ to server $b$. Each server computes, for every $j \in S$,

$$h_{b,j} = \sum_i \mathsf{Eval}(k_{i,b}, j),$$

and $h_{0,j} + h_{1,j}$ counts exactly the clients with $\alpha_i = j$, while DPF security hides every individual input from a single server. Prio was the first practical system for private aggregation at scale; it uses standard secret sharing rather than DPFs, but its authors noted DPFs could compress share size in cases such as histograms.

Private heavy hitters. The histogram protocol needs $S$ small enough to enumerate, which fails for exponentially large domains such as arbitrary URLs or search queries. The heavy hitters problem asks for the most frequent strings among clients without learning individual inputs or enumerating the domain. The Poplar protocol uses an incremental variant of the tree-based DPF that allows evaluation on any prefix of an input: clients submit incremental DPF keys encoding their string, and servers progressively expand only frequently occurring prefixes rather than the whole domain. Doplar builds on Poplar, reducing the rounds of server interaction needed to verify that client submissions are well formed.

Anonymous messaging. Riposte is an anonymous bulletin board where servers hold shares of the messages for a time period. A client publishing $m$ uses private writing to insert it at a random position, sending a DPF key to each server; after all clients submit within an epoch the servers reconstruct the board, and DPF security hides which client wrote which row. Write collisions are the main challenge: two clients writing the same row sum their messages and corrupt both. Riposte enlarges the database to accommodate the expected number of writes and adds algebraic error correction to recover from a small number of collisions.

Verifiable DPF via arithmetic sketching. A malicious client could submit keys not encoding a valid point function, or with a nonzero point out of range, corrupting aggregation. One mitigation is information-theoretic arithmetic sketching. Example: prove a DPF with $N = \mathrm{poly}(\lambda)$ and outputs shared over a finite field $\mathbb{F}$ of characteristic $> 2$ encodes a single nonzero $\beta \in \{0,1\}$. After receiving the keys, the servers agree on common randomness $r_1, \dots, r_N \in \mathbb{F}$ (e.g. from a shared PRF key). With $(y_1, \dots, y_N)$ the full evaluation vector, they compute shares of $z_1 = \sum y_i r_i$ and $z_2 = \sum y_i r_i^2$ and use a small 2-PC to check $z_1^2 = z_2$. This holds iff

$$0 = \left(\sum_{i=1}^{N} y_i r_i\right)^2 - \sum_{i=1}^{N} y_i r_i^2 = \sum_{i=1}^{N} (y_i^2 - y_i) r_i^2 + \sum_{1 \leq i < j \leq N} 2 y_i y_j r_i r_j.$$

Read as a degree-2 polynomial in $(r_1, \dots, r_N)$: if two outputs $y_i, y_j$ are nonzero the monomial $r_i r_j$ has nonzero coefficient (characteristic is not 2), so by Schwartz-Zippel the verification passes with probability at most $2/|\mathbb{F}|$. If only $y_i$ is nonzero but lies outside $\{0,1\}$ then $y_i^2 - y_i \neq 0$ and Schwartz-Zippel applies again. Related sketches test other relations, other choices of $\beta$, arbitrary finite fields, and weight-$w$ vectors for verifying DMPFs.

Verifiable DPF via hashing. Relying on the tree structure, extend the tree by one level so outputs grow from $N$ to $2N$; the extra $N$ values are all zero, so both servers obtain the same shares (after correcting for sign). The servers hash the $N$ extra shares, exchange, and compare. Under certain collision-resistance and correlation-intractability assumptions on the hash function this guarantees consistency of the DPF outputs even if one server is malicious. The technique first appeared for verifying consistency of a distributed puncturable PRF protocol. It has lower round complexity than sketching, since no shared randomness and no general-purpose 2-PC are needed, but cryptographic hashing can cost more than finite-field operations.

Extractable DPF. Both verification approaches cost computation linear in the domain size. Some applications instead verify only on a subset of the domain, as done for heavy hitters. But if the subset is unknown at $\mathsf{Gen}$ time this enables a subtle attack: a malicious client submits a query with several nonzero locations and is caught only if the subset of interest contains two or more of them, effectively casting several votes.

Extractable DPF blocks this double voting. The query structure ensures a malicious client can pick only one point at which the sum of evaluations takes a permissible nonzero value, where only a small subset of the output group is permissible. Formally, a 2-party extractable DPF in the Random Oracle Model has a polynomial-time extractor which, given the keys produced by $\mathsf{Gen}$ and all of $\mathsf{Gen}$'s random-oracle calls, outputs a location $\alpha$. The adversary wins if $\mathsf{Eval}(0,k_0,\alpha^*) + \mathsf{Eval}(1,k_1,\alpha^*) = \beta$ for some $\alpha^* \neq \alpha$ and nonzero permissible $\beta$; the scheme is secure if that probability is negligible.

The tree-based DPF of the Algorithms appendix was proven extractable under two assumptions: the PRG is modeled as a random oracle, and the output group is sufficiently large. Several other constructions are not extractable, including the less efficient two-party DPFs and the multi-party DPFs mentioned earlier. Intuitively the tree scheme is extractable because a malicious client cannot control more than one nonzero path in the GGM tree. At level $i$ an honest client uses its single correction word to zero the subtree rooted at the off-path child. A malicious client has two strategies. It can supply a correction word that zeroes neither child, but then modeling the PRG as a random oracle makes all two-or-more nonzero values random and independent, so at most one leaf's final output is controllable, and if the output group is large relative to the permissible set the chance that more than one point is permissible is negligible. Or it can give different correction words to the two servers: each key has a private part (the root seeds, sampled independently) and a public part (the correction words, identical in an honest run), so the servers run a secure protocol checking their public parts match.

Summarizing the analysis: with input domain $\{0,1\}^n$, output group $G$, permissible set $P \subseteq G$, the PRG modeled as a random oracle, a malicious client making at most $t$ PRG calls, and the servers securely testing that the public key parts agree, the DPF is extractable and the client wins with probability at most

$$\frac{O\!\left((t^2 + nt)\,|P|\right)}{|G|}.$$

Application: Secure Computation with Preprocessing

Efficient secure two-party computation is often split into an input-independent preprocessing phase, where a trusted dealer or a cryptographic protocol distributes correlated randomness, and a lightweight online phase. The FSS-based approach generalizes the TinyTable protocol: where TinyTable stores per-gate correlated randomness as a full truth table (exponential in the number of input wires), the FSS-based approach replaces truth tables with FSS keys, compressing exponentially for gate types with efficient FSS. Later work extended it to mixed-mode computation where different circuit parts work over different algebraic domains.

Single gate. For a gate $g : G_{\mathrm{in}} \to G_{\mathrm{out}}$, suppose both parties know a masked input $\hat w = w + r_{\mathrm{in}}$ for a random mask $r_{\mathrm{in}}$ unknown to either individually. Knowing $r_{\mathrm{in}}$ and a random output mask $r_{\mathrm{out}}$, the dealer precomputes the offset function

$$g_{r_{\mathrm{in}}, r_{\mathrm{out}}}(\hat w) = g(\hat w - r_{\mathrm{in}}) + r_{\mathrm{out}} = g(w) + r_{\mathrm{out}}$$

and distributes FSS keys for it. Online, both parties evaluate their keys on the common $\hat w$, obtaining additive shares of $g(w) + r_{\mathrm{out}}$, exchange them, and recover the masked output, which is itself a fresh masking feeding the next gate.

Whole circuit. The dealer associates a random mask $r_j$ with every wire $j$ and prepares FSS keys for each gate's offset function. The invariant is that both parties learn $w_j + r_j$ for every wire $j$: established at the inputs by each party sending its masked input, and advanced gate by gate by the above. At the end the dealer reveals the output-wire masks. The gain over TinyTable is storing FSS keys instead of full truth tables; for gates with compact FSS, such as comparison and equality via DCF and DPF, the per-gate correlated randomness is exponentially smaller than the truth table. (A general method for compressing truth-table correlations exists, but its running time still grows linearly with truth-table size, i.e. exponentially in gate input length.) A variant makes the correlated randomness circuit-independent by choosing gate masks independently and providing additive shares of the input masks alongside the keys, so parties non-interactively reconcile mask mismatches online at the cost of one group element per wire rather than per wire value.

Instances. Several known protocols are special cases. A ring-product gate $g(x_1,x_2) = x_1 \cdot x_2$ has an offset-class FSS scheme that reduces to the Beaver triple technique; Boolean gates on few input bits with truth-table FSS recover TinyTable. Using DPF- and DCF-based FSS, these nonlinear gates get compact correlated randomness and optimal online communication:

  • Equality test and integer comparison, via DPF and DCF respectively.
  • Bit decomposition of an arithmetic sharing over a large group, by composing comparison gates.
  • Fixed-point arithmetic such as truncation and rounding, expressed with comparison-based gates.
  • Nonlinear activation functions, via piecewise-linear or piecewise-polynomial approximations of ReLU or sigmoid using a small number of comparison and arithmetic gates.

This makes the approach especially useful for privacy-preserving machine learning, mixing linear operations (matrix multiplication over arithmetic shares) with nonlinear ones (activations, argmax); systems built on it have shown FSS-based techniques to be competitive for such mixed-mode computation.

Application: Pseudorandom Correlation Generators and Functions

A PCG has a key generation producing a pair of short correlated seeds that expand locally (silently) into a large quantity of correlated randomness, such as a batch of random OT correlations or Beaver triples. Security means one seed $s_i$ reveals no more than the target correlation implies: for random OT, $s_0$ hides $P_1$'s selections and $s_1$ hides the unselected bits of $R_0$.

Sparse-vector sharing. A weight-one vector $\vec v = (0, \dots, \beta, 0, \dots, 0) \in R^N$ over a ring $R$ is the truth table of $f_{\alpha,\beta} : [N] \to R$, so a dealer shares $\vec v$ by handing out a pair of DPF keys; a multi-point DPF extends this to weight-$t$ vectors for moderate $t$.

Vector-OLE. The dual form of LPN over $R$ states that for a secret sparse $\vec e \in R^n$ and public random $H \in R^{m \times n}$, the product $H \vec e$ is computationally indistinguishable from random (the syndrome decoding problem). In a vector-OLE correlation one party holds $\vec u, \vec v$ and the other holds a scalar $x$ and learns $\vec w = \vec u x + \vec v$. Viewing vector-OLE as a subtractive sharing of $\vec u x$, define the pseudorandom $\vec u$ as an LPN instance $H \vec e$, and use a multi-point DPF to share $\vec e x$, which has the same sparsity as $\vec e$. After expanding the DPF seeds each party locally multiplies its share vector by $H$ to obtain $\vec v$ or $\vec w$. The seeds additionally give one party $x$ and the other the sparse $\vec e$.

Correlated and random OT. Vector-OLE generalizes to correlated OT, where each sender message pair satisfies $m_{i,0} + m_{i,1} = \Delta$ for a fixed secret offset $\Delta$. This is equivalent to vector-OLE with $u_i \in \{0,1\}$, also called subfield vector-OLE when $R$ is a binary extension field; correlated OT converts into standard random OT by passing the messages through a correlation-robust hash function.

Batch OLE via a tensor trick. For OLE correlations $w_i = u_i x_i + v_i$ with all $u_i, v_i, x_i$ independently random, sample two LPN error vectors $\vec e, \vec e\,' \in R^n$ and set $\vec u = H \vec e$, $\vec x = H \vec e\,'$. Then

$$\vec u \cdot \vec x^{\top} = H \cdot \vec e \cdot (\vec e\,')^{\top} H^{\top}.$$

The tensor product $\vec e \cdot (\vec e\,')^{\top}$ has at most $t^2$ nonzero entries, so it can be shared with a $t^2$-point DPF of domain size $N^2$. The parties then locally compute shares of $\vec u \cdot \vec x^{\top}$ and take the diagonal to obtain shares of $u_i x_i$ for all $i$; as a by-product they can compute shares of any bilinear function of $\vec u$ and $\vec x$.

Optimizations. The vector-OLE construction came first; OT and OLE followed. Practical constructions replace the uniform $H$ with a structured matrix admitting fast multiplication, relying on a structured LPN variant: $H$ may be quasi-circulant, a polynomial multiplication matrix (ring-LPN), or the parity-check matrix of a carefully designed code family with fast encoding and good minimum distance. Some works use the primal form $A \vec s + \vec e$ instead of the dual, and in the sparse-LPN variant each row of $A$ is sparse, significantly speeding up computation.

Pseudorandom correlation functions. A PCF is to a PCG what a PRF is to a PRG: instead of expanding seeds into a fixed-size batch, it supports a virtually unbounded number of correlated instances. A PCF for simple correlations such as OT follows from any FSS scheme for a class of (weak) PRF. An LWE-based feasibility follows from FSS for general circuits but is impractical. The first concretely efficient PCF relied on a new weak PRF candidate in which a function is a sum of point functions on variable-size subsets of the input, so an FSS scheme for the class follows from multiple DPF instances. Subsequent PCF constructions cover OT and other correlations.

Application: Locally Random Reductions

A complexity-theoretic application. Classical arithmetization reduces evaluating $f(x)$ to evaluating a related function $g$ on inputs $x_1, \dots, x_n$ each of which is individually random, and if $f \in \mathrm{PSPACE}$ or $\mathrm{EXPTIME}$ then so is $g$. This is an $n$-query locally random reduction (LRR), and it gives a worst-case to average-case reduction: from an oracle $A_g$ correct on all but an $\epsilon$-fraction of inputs, one builds a probabilistic $A_f$ correct on all inputs except with error probability $\epsilon n$, by invoking $A_g$ on $x_1, \dots, x_n$ and union-bounding.

A 2-party DPF gives a similar LRR with only 2 queries: on input $x$, run $\mathsf{Gen}(x)$ to get $k_0, k_1$, and let $g$ be the DPF $\mathsf{Eval}$ function. For existing DPF constructions, if $f \in \mathrm{PSPACE}$ or $\mathrm{EXPTIME}$ then so is $g$. The catch is a weaker LRR notion where each query is pseudorandom rather than perfectly random (pseudorandomness of keys does hold for standard constructions). Assuming a sub-exponentially secure PRG, which follows from a similarly secure one-way function, the pseudorandomness is good enough to fool an $A_g$ running in fixed exponential time while key generation stays polynomial time. The result is a worst-case to average-case reduction for $f \in \mathrm{PSPACE}$ or $\mathrm{EXPTIME}$ with 2 queries: if $A_g$ is correct on all but an $\epsilon$-fraction of inputs, $A_f$ errs with probability at most $2\epsilon$. Extending the idea to efficiently checking polynomial-time computable functions has been explored, but requires FSS or HSS for more complex classes, currently only constructible from public-key assumptions such as LWE.

Open Questions

  • Improved 2-party DPF. Can the $\approx n \cdot \lambda$ key size of the best PRG-based construction be improved? Even concrete improvements such as a better multiplicative constant are highly motivated. Alternatively, can a barrier be formalized given only a restricted set of computational operations?
  • Multi-party DPF. Can the square-root key-size barrier be beaten for PRG/OWF-based full-threshold multi-party DPF? Specifically, is there a 3-party DPF secure against two corruptions with key size $O(\lambda \cdot 2^{(1/2-\epsilon)n})$ for constant $\epsilon > 0$? A canonical milestone is $O(\lambda \cdot 2^{n/3})$, but any constant improvement in the exponent would be a major advance.
  • FSS for conjunctions. Which assumptions suffice for efficient FSS for arbitrary conjunctions of input bits? Are one-way functions enough, or does this imply public-key cryptography? Conjunctions of up to $d$ bits are achievable with key size $O(2^d)$.
  • Efficient distributed $\mathsf{Gen}$. Is there a distributed generation algorithm making black-box use of a PRG with computation polylogarithmic, or even just sublinear, in the domain size? Existing protocols are either non-black-box in the PRG or require linear computation.
  • Information-theoretic DPF. Is there a perfectly secure 3-party DPF with domain size $N$ and key size $N^{o(1)}$, for threshold $t = 1$? Such a 4-party DPF, or alternatively a statistically secure 3-party DPF, is known. Also: what is the minimal key size of an information-theoretic 2-party DPF with compact output shares (say 2 bits long) if general non-additive reconstruction is allowed, and what is the power of information-theoretic FSS in that setting?

Algorithms

The survey presents one formal algorithm in full, the optimized two-party tree-based DPF (the scheme of Theorem 3.1). Everything else is given as construction sketches in prose. The remaining listings below are written out from the survey's textual descriptions so the appendix is self-contained.

Algorithm 1: Optimized two-party DPF $(\mathsf{Gen}^\bullet, \mathsf{Eval}^\bullet)$

Let $G : \{0,1\}^\lambda \to \{0,1\}^{2(\lambda+1)}$ be a PRG and $\mathsf{Convert}_{\mathbb{G}} : \{0,1\}^\lambda \to \mathbb{G}$ a map taking a random $\lambda$-bit string to a pseudorandom group element of $\mathbb{G}$. The symbol $\Vert$ denotes concatenation; subscripts $0,1$ are party ids; all $s$ values are $\lambda$-bit strings and all $t$ values single bits.

Gen*(1^lambda, alpha, beta, GG):
  Input:  security parameter lambda, point alpha in {0,1}^n, payload beta in GG
  Output: key pair (k_0, k_1)
 1: let alpha = alpha_1, ..., alpha_n be the bit decomposition of alpha
 2: sample random s_0^(0) <- {0,1}^lambda and s_1^(0) <- {0,1}^lambda
 3: let t_0^(0) = 0 and t_1^(0) = 1
 4: for i = 1 to n do
 5:     s_0^L || t_0^L | s_0^R || t_0^R  <- G(s_0^(i-1))
        s_1^L || t_1^L | s_1^R || t_1^R  <- G(s_1^(i-1))
 6:     if alpha_i = 0 then Keep <- L, Lose <- R
 7:     else Keep <- R, Lose <- L
 8:     end if
 9:     s_CW <- s_0^Lose XOR s_1^Lose
10:     t_CW^L <- t_0^L XOR t_1^L XOR alpha_i XOR 1
        t_CW^R <- t_0^R XOR t_1^R XOR alpha_i
11:     CW^(i) <- s_CW || t_CW^L || t_CW^R
12:     s_b^(i) <- s_b^Keep XOR t_b^(i-1) . s_CW           for b = 0, 1
13:     t_b^(i) <- t_b^Keep XOR t_b^(i-1) . t_CW^Keep      for b = 0, 1
14: end for
15: CW^(n+1) <- (-1)^(t_1^(n)) . ( beta - Convert(s_0^(n)) + Convert(s_1^(n)) )  in GG
16: let k_b = s_b^(0) || CW^(1) || ... || CW^(n+1)
17: return (k_0, k_1)

Eval*(b, k_b, x):
  Input:  party index b in {0,1}, key k_b, input x in {0,1}^n
  Output: share y_b in GG of f_{alpha,beta}(x)
 1: parse k_b = s^(0) || CW^(1) || ... || CW^(n+1); let t^(0) = b
 2: for i = 1 to n do
 3:     parse CW^(i) = s_CW || t_CW^L || t_CW^R
 4:     tau^(i) <- G(s^(i-1)) XOR ( t^(i-1) . ( s_CW || t_CW^L || s_CW || t_CW^R ) )
 5:     parse tau^(i) = s^L || t^L | s^R || t^R  in {0,1}^{2(lambda+1)}
 6:     if x_i = 0 then s^(i) <- s^L, t^(i) <- t^L
 7:     else s^(i) <- s^R, t^(i) <- t^R
 8:     end if
 9: end for
10: return (-1)^b . ( Convert(s^(n)) + t^(n) . CW^(n+1) )  in GG

Algorithm 2: Square-root DPF (warmup)

Gen_sqrt(1^lambda, alpha, beta):
  Input:  alpha in [N] with N = l^2, payload beta, PRG G: {0,1}^lambda -> {0,1}^l
  Output: (k_0, k_1) of size O(sqrt(N))
 1: view the target vector u in Z_2^N (u_alpha = beta) as an l x l matrix M;
    let i be the row of M containing alpha and j* the column of alpha within row i
 2: for each row j != i: sample one seed s^j <- {0,1}^lambda, place it in BOTH keys
 3: for row i: sample independent seeds s_0^i, s_1^i and place s_b^i in key k_b
 4: for each row j: place additive shares [t^j] of the control bit
        t^j = 1 if j = i, else 0
 5: CW <- G(s_0^i) XOR G(s_1^i) XOR (0, ..., beta, ..., 0)   // beta at column j*
 6: place the public CW in both keys
 7: return (k_0, k_1)                       // (lambda+1).l secret bits + l public bits

Eval_sqrt(b, k_b, x):
 1: write x as (row j, column c)
 2: row_b <- G(s_b^j)                        // s_b^j = s^j for j != i
 3: row_b <- row_b XOR ( t_b^j . CW )        // conditional correction
 4: return the c-th entry of row_b
// Rows with shared seeds cancel under XOR (zero rows); row i expands to a
// pseudorandom row that CW corrects to place beta at column j*.

Algorithm 3: DCF from DPF, generic reduction (Equation 1)

Gen_DCF(1^lambda, alpha, beta):
 1: for i = 1 to n:
 2:     alpha^i <- alpha_1 alpha_2 ... alpha_{i-1} 0 alpha_i
 3:     (k_0^i, k_1^i) <- Gen_DPF(1^lambda, f_{alpha^i, beta})
 4: return k_b = (k_b^1, ..., k_b^n)

Eval_DCF(b, k_b, x):
 1: y <- 0
 2: for i = 1 to n:
 3:     x^i <- x_1 x_2 ... x_i 1
 4:     y <- y + Eval_DPF(b, k_b^i, x^i)
 5: return y      // sum over n mutually exclusive conditions equals f^<_{alpha,beta}(x)

// With the tree-based DPF and GG = Z_2, beta = 1, the SAME DPF key already serves
// as a DCF key: the tree yields shares of f_{alpha',beta} for every prefix alpha'
// of alpha, so each term is computed locally. If x_i = 1 the i-th term is 0 and is
// dropped; if x_i = 0 the term equals f_{alpha', beta}(x_1 ... x_{i-1} 1) for the
// length-i prefix alpha'. General GG and beta cost about n.log|GG| extra
// correction bits per key.

Algorithm 4: Black-box distributed key generation for the tree-based DPF

DistGen(P_0, P_1):
  Input:  bitwise shares of alpha, additive shares of beta in GG
  Output: k_b to party P_b; black box in OT and the PRG
 1: each party b samples its own random initial seed s_b^(0)
 2: for i = 1 to n do                       // sequential: log N = n rounds
 3:     each party expands all level-i seeds to double length and splits the
        results into left halves and right halves
 4:     party b locally computes L XOR s_{b,l}  (XOR of all left halves)
        and                     R XOR s_{b,r}  (XOR of all right halves)
        where L, R depend only on off-path nodes and are common to both parties
 5:     P_0 acts as OT sender:
            if its share of alpha_i is 0: m_0 <- L XOR s_{0,l}, m_1 <- R XOR s_{0,r}
            else                        : swap m_0 and m_1
 6:     P_1 acts as OT receiver with choice bit b = its share of alpha_i, learns m_b
 7:     P_1 computes CW^(i) = m_b XOR (L XOR s_{1,l})   if b = 0
                             m_b XOR (R XOR s_{1,r})   if b = 1
 8:     P_1 sends CW^(i) to P_0
 9: end for
10: // last correction word needs no OT
    each party expands its seed at all leaves into elements of GG;
    CW^(n+1) <- fixed linear combination of these values and the shares of beta
11: return k_b = s_b^(0) || CW^(1) || ... || CW^(n+1)
// Cost: O(2^n) PRG expansions, exactly n string OTs, n sequential rounds.
// If leaking alpha (but not beta) to one party is allowed, all OTs run in
// parallel and 2 rounds suffice.

Algorithm 5: Arithmetic-sketching verification of a DPF key pair

VerifyDPF(servers S_0, S_1; keys k_0, k_1; field FF with char(FF) > 2):
  Goal: check the keys encode a single nonzero output beta in {0,1}
        (domain size N = poly(lambda))
 1: servers agree on common randomness r_1, ..., r_N in FF
    (e.g. derived from a shared PRF key)
 2: each server b computes its shares of the full evaluation vector
        (y_1, ..., y_N)  via FullEval(b, k_b)
 3: each server b computes shares of
        z_1 = sum_i y_i . r_i
        z_2 = sum_i y_i . r_i^2
 4: run a small 2-PC protocol to check  z_1^2 = z_2
 5: accept iff the check passes
// Soundness: the check is a degree-2 polynomial identity in (r_1,...,r_N).
// Two nonzero outputs y_i, y_j leave a nonzero coefficient on r_i.r_j (char != 2);
// a single nonzero y_i outside {0,1} leaves y_i^2 - y_i != 0. By Schwartz-Zippel a
// bad key passes with probability at most 2/|FF|.

Algorithm 6: Hash-based verifiable DPF

VerifyDPF_hash(servers S_0, S_1; keys k_0, k_1; hash H):
 1: the DPF tree is generated with one extra level, so outputs number 2N
    instead of N; the extra N values are all zero by construction
 2: each server b computes the extra N output shares via FullEval
 3: each server b computes h_b = H(its N extra shares)   // after sign correction
 4: servers exchange h_0, h_1 and accept iff h_0 = h_1
// Under collision-resistance and correlation-intractability assumptions on H this
// guarantees consistency of the DPF outputs even against one malicious server.
// Lower round complexity than sketching (no shared randomness, no general 2-PC),
// but hashing can cost more than field operations.

Algorithm 7: FSS-based secure computation with preprocessing

Preprocess(circuit C):
 1: for every wire j of C: sample a random mask r_j
 2: for every gate g with input wire j and output wire j':
        build the offset function  g_{r_j, r_{j'}}(w^) = g(w^ - r_j) + r_{j'}
        (k_0^g, k_1^g) <- FSS.Gen(1^lambda, g_{r_j, r_{j'}})
 3: give party P_b all keys k_b^g

Online(inputs):
 1: each party masks its own inputs and sends them to the other, so both parties
    hold w^_j = w_j + r_j for every input wire j
 2: for each gate g in topological order:
 3:     each party b computes  y_b <- FSS.Eval(b, k_b^g, w^_j)
 4:     parties exchange y_0, y_1 and set w^_{j'} = y_0 + y_1 = g(w_j) + r_{j'}
 5: end for
 6: dealer reveals the output-wire masks; parties unmask the results
// Product gates recover Beaver triples; small Boolean gates recover TinyTable;
// equality and comparison gates use DPF and DCF respectively.

Algorithm 8: PCG for vector-OLE from DPF/DMPF and LPN

PCG.Gen(1^lambda):
  Public: matrix H in R^{m x n}; sparsity t
 1: sample sparse e in R^n with weight t, and a scalar x in R
 2: (k_0, k_1) <- DMPF.Gen for the t-point function whose truth table is  e . x
 3: seed_0 <- (k_0, e)   ;   seed_1 <- (k_1, x)
 4: return (seed_0, seed_1)

PCG.Expand(b, seed_b):
 1: v_b <- DMPF.FullEval(b, k_b)          // shares of the sparse vector e.x
 2: output H . v_b  (plus u = H.e for the party holding e, and x for the other)
// Result: one party holds u, v and the other holds x, w with w = u.x + v.
// Correlated OT is vector-OLE with u_i in {0,1} (subfield vector-OLE); random OT
// follows by hashing the messages with a correlation-robust hash.

// Batch OLE, tensor trick:
 1: sample sparse e, e' in R^n; set u = H.e and x = H.e'
 2: u . x^T = H . e . (e')^T . H^T, and e.(e')^T has at most t^2 nonzero entries
 3: share e.(e')^T with a t^2-point DPF over domain N^2
 4: parties locally compute shares of u . x^T and take the diagonal, obtaining
    shares of u_i . x_i for all i (and of any bilinear function of u and x)
